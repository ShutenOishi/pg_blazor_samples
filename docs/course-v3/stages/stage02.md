# 第2段階の概要：Blazorの基本と実行原理

## この段階の目的

第1段階では、Web開発の入口となるHTML・CSS・HTTP・ブラウザーの開発者ツールを使いました。第2段階では、同じ画面をRazorで作り、C#の値を表示し、ボタン操作からサーバー側のメソッドを呼ぶところまで進みます。さらにSignalR・circuit・事前レンダリング・入力値・状態の保存先を段階的に理解します。WinForms＋Dapperの経験を活かすには、C#の言語知識をそのまま使える部分と、Web特有の通信や状態の寿命を新しく学ぶ部分を分けて考えると効果的です。

**学習範囲：006〜020の15本**。各5本のあとに第2・3・4組の復習を行います。データベース接続、AD本人認証、IIS実機構築はこの段階の実習では不要です。Visual Studio 2026、.NET 10、起動済みのWebアプリとChromeがあれば操作できます。

## 2. WinFormsとの役割の違い

| 観点 | WinForms＋Dapper | この教材のBlazor |
| --- | --- | --- |
| 画面の部品 | FormとControl | RazorコンポーネントとHTML |
| C#イベント | 多くは利用者PCで実行 | Interactive ServerではWebサーバーで実行 |
| ページ移動 | フォームを開く | URLから@pageに対応する画面へ移動 |
| 値の表示 | Label.Textなど | @変数・@式でHTMLに反映 |
| 状態 | Formインスタンスが保持 | コンポーネント・対話接続などの寿命に依存 |
| 永続化 | DapperからDBへ保存 | 画面の値は自動的にDBへ保存されない |

同じPCでブラウザーとサーバーを起動していると、C#がすべてブラウザー側で動いているように感じることがあります。実際の処理場所はコード・レンダーモード・通信方式に基づいて確認してください。

## 3. 画面コードと実行方式を先に読む

学習順006の実画面では次のようにURLと日本語見出しを定義しています。

```razor
@page "/learn/006"
<PageTitle>ステップ01：最初の画面｜Blazor ステップアップ学習</PageTitle>
<h1>はじめてのBlazor画面</h1>
```

対話型のカウンターは学習順009で次のように定義されています。

```razor
<p>サーバーでの操作回数：<strong data-testid="runtime01-count">@count</strong></p>
<button type="button" @onclick="Increment">サーバー側の回数を増やす</button>
```

前者は画面のURLと表示です。後者にはイベントがあり、接続が成立して初めてボタン操作をサーバーC#で処理します。`App.razor`の`<Routes @rendermode="InteractiveServer" />`により、この教材アプリのルートは対話型に設定されています。学習順009はStatic SSRの説明を掲示しますが、別のStatic SSR専用アプリを実際に起動する比較ではありません。

## 6. 第2組の確認演習と解答

**問題1：** 学習順008で表示した山括弧の文字列がHTMLタグにならないのはなぜでしょうか。

**解答：** 通常のRazor文字列出力ではHTMLエンコードされるためです。タグ風のテキストと実際のDOM要素の違いをElementsで調べます。

**問題2：** 学習順009のボタンを2回押すと2になります。この値はデータベースの監査記録ですか。

**解答：** いいえ。コンポーネントのサーバー側フィールドです。永続的な監査記録や利用者の本人識別は別途必要です。

**問題3：** 学習順010で0のとき減らすボタンは無効です。処理側の`if (count > 0)`は必要ですか。

**解答：** 必要です。利用者の操作性を改善する`disabled`と、C#処理側の制約は役割が異なるためです。後の業務画面でサーバー側の権限制御を学ぶ土台になります。

第2組の受入後も、学習順011〜020は別の組として全面改稿します。この段階全体を完了済みとは扱いません。

## 7. 第3組011〜015の学習と第4組への引き継ぎ

第3組では、画面の表示だけでなく値の所有者を確認します。学習順011は空文字列・空白だけの入力と消去ボタンを比べ、012は4件の固定配列から表示対象の2件を選びます。013では親の入力を1枚目のカードへ渡し、014では子の選択結果を親へ通知します。015では同じC#の状態でも再読込や回線切断によって寿命が変わることを確かめます。

| 学習順 | URL | 観察すること |
| --- | --- | --- |
| 011 | /learn/011 | oninputと文字列のHTMLエンコード |
| 012 | /learn/012 | 未完了2件を絞り込み、4件へ戻る |
| 013 | /learn/013 | 子カード2枚のうち1枚だけが変わる |
| 014 | /learn/014 | EventCallbackで通知すると選択回数が増える |
| 015 | /learn/015 | circuitの一時状態と再読込による初期化 |

~~~razor
<GreetingCard LearnerName="@learnerName" Topic="親が入力した名前" />
<TopicPicker SelectedTopic="@selectedTopic" OnSelected="OnTopicSelected" />
~~~

親から子の入力と子から親への通知は逆向きです。二つの部品が同じ形式で状態を更新するわけではありません。第3組の復習ではこの違いをコードで読み取り、SignalRで画面が動いていても業務DBへ自動保存されないことを説明してください。

**問題：** 親が値を更新しなくても、子がParameterへ代入すれば一貫した状態になりますか。

**解答：** なりません。親が次の描画で値を再設定する可能性があります。変更が必要な場合は子から親へ通知し、親が状態を更新します。再接続後の状態復元も自動保証ではありません。

## 8. 第4組016〜020と第2段階のまとめ

第4組では、初期化・Parameter変更・破棄、事前レンダリングの初期化回数、フォームの日本語検証、再読込とURLの状態、circuit・ブラウザー・DBの保存先をつなげて学びます。WinForms＋Dapperで慣れたLoadやValidating、フィールドやDB保存の責務が、Webではどの場所と寿命に対応するかを確認してください。

| 学習順 | URL | 画面で確かめること |
| --- | --- | --- |
| 016 | /learn/016 | 子のParameter更新と新しいインスタンスの生成 |
| 017 | /learn/017 | 事前レンダリング側と対話側の初期化を区別 |
| 018 | /learn/018 | 必須・文字数の日本語検証と画面内の確認結果 |
| 019 | /learn/019 | URLのtabは残り、countは再読込で0に戻る |
| 020 | /learn/020 | 保存先の候補を選ぶが実際の保存処理は行わない |

~~~csharp
[SupplyParameterFromQuery(Name = "tab")]
[Parameter] public string? Tab { get; set; }
private int count;
private void Increase() => count++;
~~~

**確認問題：** 「履歴」タブを選択して操作回数を2にした後、再読込するとどうなりますか。

**解答：** URLにあるtab=historyは再読込後にも読み取れるため、「履歴」の表示が残ります。しかしcountは新しいコンポーネントのフィールド初期値0へ戻ります。URLは認証・業務認可の証拠になりません。第2段階を終える前に、[第4組の復習](../reviews/review-04.md)で5画面を操作し、次の[学習順021：DIの基本](../../samples/step11.md)に進んでください。
