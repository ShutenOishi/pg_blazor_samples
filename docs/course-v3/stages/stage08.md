# 第8段階の概要：監査・競合制御・Windows Server運用

> 教材v3の**完成後の構成案**。この段階の新規項目が未実装の場合、現行教材へ実装済みとして掲載しません。

## この段階でできるようになること
鍵・Cookie、権限行ロック、監査の同一トランザクション、IIS/障害復旧の受入範囲を判断できる。

## この段階の前提
第7段階の認証認可とPostgreSQL。現地のIIS/AD/FDWは環境依存。

## WinForms・Dapperとのつながり
デスクトップ単体実行とは違い、複数利用者・再接続・サーバー側の状態失効と監視が必要になる。

## 学習の順番と到達点
- 学習順096：既存台帳のキー正規化・重複拒否と索引（旧Step71に対応）
- 学習順097：明示Windowsログインと短命Cookie（旧Step72に対応）
- 学習順098：権限行ロックと更新の原子性（旧Step73に対応）
- 学習順099：本人・操作・結果を永続監査する（旧Step74に対応）
- 学習順100：IIS・Kerberos・負荷・障害の実機受入（旧Step75に対応）
- 学習順101：二人の編集競合とxmin（旧Step76に対応）
- 学習順102：キャッシュの有効期限と権限失効（旧Step77に対応）
- 学習順103：ヘルスチェック・構造化ログ・運用監視（旧Step78に対応）
- 学習順104：実DB・ブラウザー・認可の結合/E2E試験（旧Step79に対応）
- 学習順105：Windows Server 2025/IISの配布・切替・復旧（旧Step80に対応）

## 練習課題と解答の確認点
権限変更競合と監査失敗の拒否、IIS受入チェック、DB実接続/CI/実機の違いを確認する。

**確認の基準：** 画面操作の結果だけでなく、処理がブラウザー・サーバー・DBのどこで動くか、例外や拒否をどう確認するかを説明できること。未実装の教材では学習結果の達成を宣言しません。
