# 第3段階の概要：DI・サービスと単体テスト

> 教材v3の**完成後の構成案**。この段階の新規項目が未実装の場合、現行教材へ実装済みとして掲載しません。

## この段階でできるようになること
DI登録、インターフェイス、ライフタイム、Options、ログ、テスト、サービス分離を一つの小さな画面で説明できる。

## この段階の前提
第2段階のcircuit/イベント。DB/AD不要。

## WinForms・Dapperとのつながり
WinFormsのnewと外部サービス注入を比較し、Scopedを画面操作ごとの生成と誤解しない。

## 学習の順番と到達点
- 学習順021：DI（依存性注入）の基本（旧Step11に対応）
- 学習順022：インターフェイスで部品を交換する（旧Step12に対応）
- 学習順023：Singleton・Scoped・Transient（旧Step13に対応）
- 学習順024：BlazorのScopedと対話回線（旧Step14に対応）
- 学習順025：injectとコンストラクター注入（旧Step15に対応）
- 学習順026：Optionsで設定を受け取る（旧Step16に対応）
- 学習順027：非同期処理とログ（旧Step17に対応）
- 学習順028：DIによる単体テスト（旧Step18に対応）
- 学習順029：Applicationへ処理を分離（旧Step19に対応）
- 学習順030：DIで課題管理を作る（旧Step20に対応）

## 5ステップごとに確認すること
- 学習順025の後：第5組の復習。直前の5テーマの関係を説明し、動作を再確認する。
- 学習順030の後：第6組の復習。直前の5テーマの関係を説明し、動作を再確認する。

## 練習課題と解答の確認点
固定時計をテストへ渡し、Scoped課題リストとIOptionsを利用して入力エラーを確認する。

**確認の基準：** 画面操作の結果だけでなく、処理がブラウザー・サーバー・DBのどこで動くか、例外や拒否をどう確認するかを説明できること。未実装の教材では学習結果の達成を宣言しません。
