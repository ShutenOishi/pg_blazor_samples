# 学習順001〜005の復習：WinFormsからWebへ

## この5ステップをつなぐ
- 001：ブラウザーに表示される画面とサーバーのC#イベント
- 002：最初のHTTP GETと、対話型イベントの通信の区別
- 003：HTMLの文書構造とCSSの見た目
- 004：DOM・Network・Consoleの診断
- 005：KestrelとVisual Studio 2026によるサーバーC#のデバッグ

## 設計の違い
| 観点 | WinForms | この教材のBlazor Interactive Server |
| --- | --- | --- |
| 表示 | OS上のフォーム | ブラウザー上のHTML |
| C#のイベント処理 | 通常PC内で実行 | Webサーバーで実行 |
| 通信 | 必要に応じてDB/APIへ接続 | 初期HTML取得と対話型接続がある |
| デバッグ | フォーム内の処理を停止 | サーバー側C#とブラウザーの診断を分ける |

## 確認問題と解答
**問1：** Web01のカウンターを変更するC#はどこで動きますか。

**答え：** サーバーです。ブラウザーに新しい表示結果が反映されます。

**問2：** Web02のページ再読み込みとWeb01のクリックは、どちらも通常のHTTP POSTですか。

**答え：** いいえ。再読み込みは主にHTTP GETを確認しますが、Blazor Interactive Serverのクリックは対話型接続で通知されます。

**問3：** Web03でCSSの枠線を変える操作は、HTMLの意味そのものを変えますか。

**答え：** 変えません。HTMLとCSSは役割が異なります。

**問4：** UI上に変化があってもConsoleやNetworkを確認する理由は何ですか。

**答え：** ブラウザーの表示だけでは通信やスクリプトの異常を判断しきれないためです。

**問5：** Visual StudioでWeb05のC#処理を追う場合、ブレークポイントはどこに置きますか。

**答え：** `Web05Page.razor` の `BreakpointSample` メソッドです。
