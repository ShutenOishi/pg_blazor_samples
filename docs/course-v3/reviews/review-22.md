# 第22組の復習：総合演習

**対象：学習順106〜110。**

## 学習のつながり
1. WinForms＋Dapperの既存業務をWebの入力・サービス・DBに分けて設計する。
2. PostgreSQL18検索のSQL生成と、DB側ページング・本人/部署ごとの認可・監査を区別する。
3. DTO編集では取消、入力検証、保存直前の最新権限、xminの競合、監査の原子性を確認する。
4. ADは本人認証とユーザー名だけに使い、既存DB台帳を権限の正本とする。
5. xUnit・PostgreSQL18実DB・Chrome実操作・Windows/Linux CIと、Windows Server2025/IIS/AD実機受入を区別する。

## 問題
1. 画面でデータが見えた利用者は、その行を編集できるか。
2. SQLが生成できた利用者は、DBの内容を読み取ってよいか。
3. 更新と監査を別のトランザクションで確定し、後で結び付ければよいか。
4. GitHub Actions成功でKerberosやIISの本番受入が終わるか。

## 解答
1. できません。編集時に現在の台帳で操作権限を再照合します。
2. できません。SQLの生成・表示と、本人認可済みの実際のDB取得は別です。
3. いいえ。更新と監査は同一トランザクションで確定し、保証できなければ更新を拒否します。
4. 終わりません。ドメイン環境の実機検証と負荷・障害復旧の証跡が必要です。
