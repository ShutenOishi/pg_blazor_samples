# 第2組の復習：Razorと実行方式の復習

## 復習の目的

学習順006〜010の5本を、それぞれ単独の画面操作として理解しただけでは、WinFormsからWebへの移行に必要な整理が不十分です。この復習では、利用者がURLを開いてからC#イベントを実行し、変更後の値をブラウザーに表示するまでの流れをまとめます。画面が表示されること、サーバー側のC#が動くこと、データベースへ保存されることを別の事実として説明できる状態を目指します。

## 1. 5本を1つの処理として整理する

| 学習順 | 実際の画面 | 主なコード | 観察すること |
| --- | --- | --- | --- |
| 006 | /learn/01 | @page、PageTitle、h1 | URLと静的な日本語表示 |
| 007 | /learn/02 | NavLink、href、Match | 別のルートへの画面遷移 |
| 008 | /learn/03 | @code、@displayName、ToString | C#の値と安全な文字列表示 |
| 009 | /learn/runtime-01 | @onclick、Increment、count | Interactive ServerのC#イベント |
| 010 | /learn/04 | disabled、Decrement、Reset | UI側と処理側の制約 |

## 2. WinFormsとの比較

| 観点 | WinForms＋Dapper | 学習済みのBlazor実装 |
| --- | --- | --- |
| 画面の住所 | Formクラスを選択 | ブラウザーがURLを指定 |
| 画面表示 | Label.Textなど | RazorのHTMLとC#式 |
| イベント | フォームのClick | @onclickでサーバーC#を呼ぶ |
| 状態の寿命 | Formインスタンス | コンポーネントと対話接続の寿命 |
| 操作の制限 | EnabledとC#条件 | disabledとメソッド内のif |
| DB操作 | Dapper等を明示して呼ぶ | ここまでの5画面では実行しない |

## 3. 学習済みの実コードを説明する

```razor
@page "/learn/03"
<dl class="value-list">
    <div><dt>表示名</dt><dd>@displayName</dd></div>
    <div><dt>表示するステップ数</dt><dd>@stepCount</dd></div>
</dl>
```

```razor
<button type="button" @onclick="Decrement" disabled="@(count == 0)">1減らす</button>
```

```csharp
private void Decrement()
{
    if (count > 0)
    {
        count--;
    }
}
```

最初のコードはC#の値をHTMLに表示します。2つ目はクリックと表示上の無効化を結び付け、3つ目は処理そのものが0未満にならない制約です。サーバー側の業務認可をHTMLのdisabledだけで代用してはいけないという考え方を、ここで確認してください。

## 4. 5画面を通した実習

1. `/learn/01`を開き、HTML見出しとブラウザーのタイトルを読みます。
2. `/learn/02`で「ステップ03へ進む」を押し、URLが変わることを確認します。
3. `/learn/03`で日付と山括弧の文字列を調べ、文字列がHTMLタグにならないことを確認します。
4. `/learn/runtime-01`で2回クリックして数値を2にします。Documentの最初のHTTP要求とボタン操作を区別します。
5. `/learn/04`で2回増やし、1回減らし、0に戻します。0のとき減らすボタンが無効なことを確認します。
6. 再読み込みしたときに数値が0へ戻ることを見て、値がDBへ保存されたわけではないことを確認します。

## 5. 症状から判断する演習

| 症状 | 確認箇所 | まず疑うこと |
| --- | --- | --- |
| /learn/02が開けない | URLと@page | ルートの不一致・サーバー未起動 |
| 名前が表示されない | @displayNameと@code | 変数名・ビルドの誤り |
| ボタンだけ動かない | 対話型接続とC#ログ | 初期HTMLとは別の通信障害 |
| 0で減らすが押せない | disabled条件 | 仕様どおりの制限 |
| 再読込で回数が消える | コンポーネントの状態 | 永続化なしの正常な初期化 |

## 6. 問題と詳しい解答

**問題A：** Static SSRの初期HTMLが表示されていれば、必ず`@onclick`が動きますか。

**解答A：** いいえ。Static SSR単独ではBlazorの対話型C#イベントは有効になりません。この教材のInteractive Serverでは接続が準備されたあと、サーバー側のイベントが動きます。教材内のStatic SSRに関する表は説明用であり、別アプリを起動して実測した結果ではありません。

**問題B：** 学習順008の文字列`<重要>これは文字列です</重要>`が画面へ安全に表示されるのはなぜですか。

**解答B：** 通常のRazor文字列出力がHTMLエンコードを行うためです。入力由来の文字列を無条件にHTMLとして扱わないことは表示面の基本です。ただし、HTMLエンコードだけで業務データの閲覧権限が成立するわけではありません。

**問題C：** 学習順010で0のとき減らすボタンが無効なのに、C#にも`if`が必要なのはなぜですか。

**解答C：** `disabled`は利用者が操作できないようにするための画面側の指定です。メソッドが守るべき条件はサーバー側でも明示し、想定外の経路でも値が0未満にならないようにするためです。

**問題D：** `/learn/04`で数値が2になったことから、DBへの保存が成功したといえますか。

**解答D：** いえません。数値はコンポーネント内のフィールドに保持しているだけで、永続化や監査記録は実装されていません。新しい画面へ戻ったり再読込したりすると初期値になります。
