# Blazor学習教材v3 再編・実装・全面改稿計画

## 判断と変更の理由

従来の「既存Step11〜30から教材本文を先に改稿し、新規30テーマを後から挿入する」順序を**中止**する。Web未経験者が先頭から学ぶには、後でSSR/HTTP/DI/DB橋渡しを差し込むと、既存教材やコラムが前提を説明する順序と食い違い、再改稿が大量に発生する。

**新しい作業順：全110件の配置を確定 → 不足30テーマを適切な位置に実装 → 概要とコラムを含む全教材を学習順001から全面改稿 → PDF・UI・テストを同じ学習順へ同期。**

## 初学者の理解の順番

- **最初にHTTPとブラウザー**：WinFormsのイベントがサーバーへの通信と違うことを先に示す。Step01より前にWeb入門5本を置く。
- **Razorと実行原理を一緒に学ぶ**：SSR、SignalR、事前レンダリング、状態の消失を、関連する既存画面の隣へ挿入する。新概念は近くの既存画面と比較する。
- **DI、次にMudBlazor**：DIを自作するだけでなく、`AddMudServices`とProviderを利用する意味を学び、日本語UIに進む。
- **ブラウザー実務をDBより前に**：ファイル、ダウンロード、JS連携、ErrorBoundary、キーボード・拡大を日本語UI総合演習の直後に置く。
- **既存のSQL/Dapper経験をEF Coreへ接続**：EFモデル導入前に比較し、LINQ検索・CRUD・トランザクションの直前/直後にSQL・DbContext・キーなしモデル・FromSqlを挿入する。
- **一覧方式を基本から高度へ**：小規模Items → MudTable ServerData → MudDataGrid ServerData → ソート/検索 → DTO編集/競合 → 仮想化/キーセット/集計・性能の判断を理解する。必要な既存ステップの再配置・実装変更は後続の順次改稿で許す。
- **WebセキュリティをAD前に**：HTTPとCookie・CSRF・Middleware・DataProtectionを先に扱い、ADは本人認証とドメイン付きユーザー名のみ、認可は既存DB/外部台帳の正本で判断する。
- **最後に運用と通し演習**：既存登録済み利用者を前提に、業務データ操作・監査・テスト・Windows Server 2025/IIS受入を結び付ける。

## 改稿のルール（全面書き直しを全対象に）

1. **初回の改稿作業は新規30本の実装がすべて配置され、学習順が確定した後、学習順001から着手**する。既存の先行改稿25本は捨てずに素材として活用するが、「最終改稿済み」とは認定しない。
2. 最終対象は**全110ステップ、5本単位の復習22本、特別コラム3本、段階概要9本**。旧通常コラム16本は再構成する。既存旧コラムURLは壊さず、再利用するか、旧章の案内と新復習への対応を設ける。
3. 本文は目的、前提、WinForms/Dapperとの差、概念がどこで動くか、完成画面、コード、処理順、失敗時の切り分け、演習・解答、次への接続を**全件**新しい前提で再構成する。単語置換やリンク修正だけは完了としない。
4. 原則5ステップを1単位とし、**単位ごとに「概要との整合 → コードとテスト → 本文全面改稿 → 5本を総括する復習コラム → Web目次/メニューとPDF目次 → CI/実ブラウザー」を一緒に受入**する。
5. 段階概要は段階が完成するのを待たず、**その段階の最初の実装/再改稿単位の前に**修正する。概要は単なるリンク目次でなく、習得目的・前提・WinForms/Dapperの比較・学習の道筋・実習・解答の目安を持つ。
6. 新番号は学習順の表示用。既存`/learn/01`〜`/learn/80`と従来の`stepNN.md`は固定IDとして保持する。新規教材は`/learn/web-01`等のIDで追加する。**PDFとWebの目次では「学習順001」等を表示し、旧IDは必要な場合だけ補足**する。
7. 新規テーマを実装する時にはサンプルRazor、説明Markdown、日本語コメント、復習Razor、テスト、PDF生成索引を同一PR内で整備する。架空データと実AD/IISの受入を混同せず、DBが必要な場合はPostgreSQL18実接続で試験する。
8. EF Core 10/Npgsql、MudBlazor.Translations、Win11/Windows Server 2025は維持。Domain/Infrastructure等の多数の新プロジェクトは増やさず、既存Web/Data・Servicesと学習用Application/Testsを活用する。実装例のDB接続は`DbContextFactory`等で操作ごとに管理する。
9. PDFには開発者向けPR・GitHubやリポジトリ情報を記載しない。**ZIPせず単体PDF**を配布し、ソース/画面と一致する内容を検査する。

## 受入・停止条件

- 学習順の各行と、Razor `@page`、Markdown、アプリ内目次、PDF収録に欠落・重複がない。
- 5本単位の復習と段階概要が先に読める。新規テーマや既存教材の前提が後ろに存在しない。
- 日本語の表示・コメントと、各種入力エラー・失敗手順・解答がある。
- **形式上の改稿済みは認めない。** 旧Stepの本文全面書き直し、実装動作とスクリーンショット/CIの照合が必要。
- Windows/Linux Releaseビルド、Chrome操作、PostgreSQL18の実DB試験、PDF生成を確認する。未成功CIや未検証の実AD/IIS/FDWを「受入済み」にしない。
- 既存の認可拒否・鍵・監査の安全条件は緩めない。外部テーブルで原子性を証明できない更新は拒否する。
