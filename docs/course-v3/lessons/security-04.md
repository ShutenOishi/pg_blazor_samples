# 学習順084：環境別設定・Secret・Data Protection鍵

## 到達目標
開発・検証・本番で接続先や証明書の構成は異なります。Secretsはソースコードや配布PDFへ含めず、適切なアクセス制御を持つ保管先で管理します。Cookie認証チケットを保護するData Protection鍵は、複数インスタンス間の共有と安全な保存、失効や復元の手順が必要です。

## 前提条件と学習環境
第6段階のデータ検索・一覧表示と、第5段階のEF Coreの操作単位のDbContextを理解している想定です。Visual Studio 2026・.NET 10・Blazor Interactive Serverで実行します。このページ自体はADやPostgreSQLの実接続を必要としません。

## 画面で確認すること
アプリの `/learn/security-04` を開き、架空の条件を変えてボタンを押してください。**表示される許可・拒否は学習用の模擬判定です。** Windows本人認証や実際の既存台帳認可を代行せず、DBにデータを書き込みません。

## コードを追いかける
```csharp
// 設定値を画面へそのまま出力しない。
var configured = !string.IsNullOrWhiteSpace(builder.Configuration.GetConnectionString("PostgreSQL"));
// 本番では鍵の共有先とACL・暗号化・バックアップを実機で受入する。
```
コードは主要部分の抜粋です。画面とサーバーの処理場所、ミドルウェアや認可サービスの責任を区別してください。

## WinForms＋Dapper経験者向けの比較
デスクトップ画面の入力・イベントと違い、Webではブラウザーからの要求を信用できません。Blazorの対話イベントはサーバーのC#で動きますが、画面に表示される操作ボタンや保存済み状態だけで本人認証・部署別権限は保証できません。

## 間違えやすい点・安全な確認方法
画面のチェックボックスは模擬設定であり、サーバーのSecrets/鍵の存在や値は照会しません。秘密を教材・ログ・GitHubの公開ソースへ記載しないでください。

## 演習問題
環境変数に接続文字列があることだけで、データ保護や監査が保証されますか？

## 解答
保証されません。接続先の権限、シークレットのアクセス権、鍵の共有、バックアップ、DB監査の構成も必要です。
