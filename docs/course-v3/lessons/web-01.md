# 学習順001：WinFormsとWebの処理場所を比較する

**実装ソース：** [対応するRazor実装](../../../src/PgBlazorSamples.Web/Components/Samples/WebFoundation/Web01Page.razor)。画面の正規URLは `/learn/001` です。

## 到達目標

このステップでは、**ブラウザーに見える画面**と**画面の操作を処理するC#プログラム**が、必ずしも同じコンピューターに存在しないことを理解します。具体的には、`/learn/001`でボタンを2回押し、表示が「2回」に変わるまでに何が起きたかを自分の言葉で説明できることが目標です。

WinFormsでC#のイベント処理に慣れている人は、Blazorでも同じ`@onclick`を見て、C#がブラウザーで実行されると考えがちです。この教材は **Blazor Web AppのInteractive Server** を使用するため、イベントを処理するC#はサーバー上で動きます。最初にこの違いを理解すると、後のDI、DbContextFactory、認証・認可、通信切断の説明がつながります。

## 1. WinFormsとInteractive Serverの対応

| 観点 | WinFormsの典型的なアプリ | この教材のBlazor Interactive Server |
| --- | --- | --- |
| 画面の描画 | Windowsのフォームとコントロール | ブラウザーがHTMLとCSSを描画 |
| C#のクリック処理 | 通常は画面と同じPCのプロセス | ASP.NET Coreのサーバープロセス |
| 操作の伝達 | 同じプロセスのイベント通知 | ブラウザーからサーバーへの対話型接続 |
| 状態の保持 | フォームのフィールドなど | サーバーのコンポーネントインスタンスなど |
| データベース操作 | Dapperから直接接続する設計もある | サーバーのサービス経由でDBへアクセス |
| ネットワーク切断 | ローカル画面は通常そのまま操作可能 | 接続が切れると対話操作に影響 |
| 閉じた画面の値 | 通常は明示保存なしで消える | コンポーネントの状態も永続保存ではない |

同じ開発PCでブラウザーとWebサーバーを起動していると、この違いは見えにくくなります。しかし、本番でWindows Server 2025上に配置すれば、利用者のPCにはブラウザー、サーバー側にはC#の画面イベントと業務処理が配置されます。

ここで扱うのは学習用のカウンターです。データベースにもADにも接続せず、認証済み利用者であることも前提にしません。

## 2. ソースコード全体を読む

実際の画面の実装は`Web01Page.razor`です。以下は、この画面で使っているRazorの主要部分をそのまま抜粋したものです。

```razor
@page "/learn/001"

<p>サーバー側で数えた操作回数：
    <strong data-testid="web01-count">@count</strong> 回</p>
<button type="button" @onclick="Increment">サーバー側で1増やす</button>
<p role="status" data-testid="web01-trace">
    @(trace.Count == 0 ? "まだ処理していません" : string.Join(" → ", trace))
</p>

@code {
    private int count;
    private readonly List<string> trace = new();

    // サーバーの学習用イベントだけを記録する。
    private void Increment()
    {
        count++;
        trace.Add($"サーバーC#：クリック{count}回目を処理");
    }
}
```

`@page`はこのコンポーネントを開くURLを指定します。`@count`はC#フィールドの現在値を表示するRazor構文です。`@onclick="Increment"`は、ブラウザーのボタン操作とコンポーネントのC#メソッドを結び付けます。`@code`の中では普段のC#と同じフィールドやメソッドを定義します。

| コードの部分 | 意味 | 主に動く場所 |
| --- | --- | --- |
| `<button>` | ユーザーが操作するHTML要素 | ブラウザー |
| `@onclick="Increment"` | ボタン操作とC#イベントを関連付ける | イベントを受け付けるブラウザーとサーバーの協調 |
| `private int count;` | コンポーネントが持つカウント | サーバー |
| `Increment()` | 1を加算するC#メソッド | サーバー |
| `<strong>@count</strong>` | 現在の値を画面へ反映する | サーバーで表示差分を生成し、ブラウザーが反映 |

`trace`はサーバー上のC#イベントで追加した非機密の実行履歴です。1回目は「クリック1回目」、2回目は「クリック1回目 → クリック2回目」と順に表示されます。これはイベント処理の観察用であり、実際のネットワーク経路の詳細ログやデスクトップ側のC#実行を証明するものではありません。ホスト名、利用者名、接続識別子は出しません。新規ページの読み込みでは履歴も初期化されます。

`type="button"`を付けているのは、このボタンをフォーム送信用のボタンと混同しないためです。単純な画面のイベントを扱う段階で、HTTPのPOSTやDB保存は発生しません。

## 3. ボタンを押したときの時系列

1. URLを開くと、ブラウザーはWebサーバーへページを要求します。
2. ブラウザーにはHTMLが表示され、Interactive Serverの対話型接続が利用可能になります。
3. 「サーバー側で1増やす」を押します。
4. ボタン操作が対話型接続を通じてサーバーへ伝えられます。
5. サーバー上の`Increment()`が`count`を0から1へ変更します。
6. Blazorが変更後の表示差分をブラウザーへ送り、表示が「1回」になります。
7. もう一度押すと「2回」になります。

この連続した処理を実装するために、自分でJavaScriptを書いたり、HTTP POSTのエンドポイントを追加したりする必要はありません。ただし、ネットワーク通信がないわけではありません。「JavaScriptを書かない」と「通信しない」は同じ意味ではない点に注意してください。

## 4. WinFormsのコードと比較する

WinFormsなら、参考として次のようなイベントハンドラーを書くことがあります。このコードは**比較用**であり、Blazor側の画面には含まれていません。

```csharp
private int count;

private void button1_Click(object sender, EventArgs e)
{
    count++;
    label1.Text = $"{count} 回";
}
```

これに対してBlazorでは、イベント後にコンポーネントを再描画する仕組みを利用します。今回の`Increment()`が`count++`だけで済むのは、Blazorが表示を更新するためです。WinFormsの`label1.Text`と、Razorの`@count`がどのように対応するかを意識してください。

## 5. 手を動かして確認する

1. Visual Studio 2026で.NET 10のWebアプリを起動し、`/learn/001`を開きます。
2. 初期表示「0回」を確認します。
3. ボタンを1回押し、「1回」になることを確かめます。
4. もう1回押し、「2回」になることを確かめます。同時に、学習用履歴が「クリック1回目 → クリック2回目」の順で増えていることを確認します。
5. `Web01Page.razor`の`Increment()`にブレークポイントを置けるなら、クリック時にC#がサーバー側で停止することを確認します。
6. ブラウザーを再読み込みした場合、コンポーネントが再作成され、カウントが初期値に戻り、履歴も「まだ処理していません」に戻ることを確認します。これはDB保存ではありません。

**観察結果：** ボタンを2回押した直後は2回、ページを新規に開き直したときの初期値は0回です。画面の状態と永続化された業務データは別のものだと分かります。

## 6. うまく動かないとき

| 症状 | 確認すること | 切り分け |
| --- | --- | --- |
| ページが開かない | URL、Kestrelが起動しているか | 最初のHTTP要求以前の問題か |
| HTMLは出るがクリックに反応しない | ブラウザーのConsole、Networkの接続 | 対話型接続が成立しているか |
| ボタンを押してもブレークポイントが止まらない | Visual Studioのデバッグ対象プロセス、場所 | サーバーC#をデバッグしているか |
| 再読み込みでカウントが0になる | `private int count`の寿命 | 故障ではなくコンポーネントの初期化か |
| 画面が接続待機と表示する | サーバー・通信経路・再接続 | ブラウザーの表示とサーバーの処理が分かれていることを確認 |

ブラウザーのDOMやConsoleに、サーバー上のC#のすべての内部状態が現れるわけではありません。また、表示が変化したからといって、DBへの保存が成功したことにもなりません。

## 7. 演習問題と解答

**問1：** 2回クリックしたとき、`Increment()`はどのプロセスで何回実行されますか。

**解答：** この教材のInteractive ServerではサーバーのC#プロセスで2回実行され、`count`が2になります。

**問2：** ブラウザー側に`count`というC#フィールドがそのまま転送されるのでしょうか。

**解答：** C#フィールド自体をブラウザー側で実行するわけではありません。サーバーが状態を保持し、その結果の表示がブラウザーに反映されます。

**問3：** 本番でデータを更新する際、画面のカウンターと同じ方法だけでよいですか。

**解答：** いいえ。カウンターは一時的な画面状態です。DB更新には入力検証・認可・競合処理・監査などが必要です。後の段階で学びます。
