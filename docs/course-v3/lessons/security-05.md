# 学習順085：接続切断・セッション失効・権限再検証

## 到達目標
Interactive Serverのcircuitはネットワーク接続の影響を受けます。再接続できてもHTTP Cookieの期限切れや既存台帳の権限変更を無視して操作を続けてはいけません。表示済みUIや一時キャッシュは最新の認可を保証しません。

## 前提条件と学習環境
第6段階のデータ検索・一覧表示と、第5段階のEF Coreの操作単位のDbContextを理解している想定です。Visual Studio 2026・.NET 10・Blazor Interactive Serverで実行します。このページ自体はADやPostgreSQLの実接続を必要としません。

## 画面で確認すること
アプリの `/learn/security-05` を開き、架空の条件を変えてボタンを押してください。**表示される許可・拒否は学習用の模擬判定です。** Windows本人認証や実際の既存台帳認可を代行せず、DBにデータを書き込みません。

## WinForms＋Dapper経験者向けの比較
デスクトップ画面の入力・イベントと違い、Webではブラウザーからの要求を信用できません。Blazorの対話イベントはサーバーのC#で動きますが、画面に表示される操作ボタンや保存済み状態だけで本人認証・部署別権限は保証できません。

## 間違えやすい点・安全な確認方法
接続が切れた場合、既に確定したDB書き込みはCancellationTokenで巻き戻せません。トランザクションと監査の原子性を維持し、再試行は重複更新を生まないように設計します。

## 演習問題
circuitが再接続した直後なら、権限が剥奪された人のCSVダウンロードを許可できますか？

## 解答
許可できません。実際のダウンロード・集計・更新などを実行するサービス側で最新の権限を照合し、失効していれば拒否します。
