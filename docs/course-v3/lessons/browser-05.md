# 学習順045：HTMLの意味・フォーカス・拡大表示の最終確認

## このステップの到達目標
色の違いだけで成功や失敗を伝えない。キーボード、画面拡大、読上げ、意味のあるHTMLと見出し構造を確認する。C#イベントでDOMを直接操作する必要はない。

## 前提・動作環境
学習順031〜040のMudBlazor・DI・Interactive Serverを学んでいる想定です。Visual Studio 2026、.NET 10のサンプルWebアプリを使い、Active Directory・PostgreSQLや実際の業務データは不要です。

## 完成画面を操作する
Webアプリの「/learn/browser-05」を開いてください。Tab・Shift+Tabだけで入力欄とボタンを操作します。文字の拡大・コントラスト切替・200%拡大を試し、入力結果が文字で伝わることを確認します。

## WinForms・Dapper経験者向けの比較
WinFormsのイベント・ファイル操作は通常同じPC上で動きます。Interactive ServerではC#イベントがサーバーで動きます。ブラウザーのDOM、ファイル選択やダウンロードなどのAPIはWeb特有の処理場所・制約を考えて設計します。

## 処理の流れ
labelとinputをfor/idで関連付け、aria-live領域で操作結果を伝える。フォーカスはCSSの:focus-visibleで判別できるようにする。Razorで拡大状態とコントラストを変える。

## 関連するC#またはRazorの実装
```razor
<label for="practice-note">表示内容</label>
<input id="practice-note" />
<p role="status" aria-live="polite">入力結果を表示</p>
```
教材のコードは主要部分の抜粋です。実際の画面は制約・例外処理や状態表示も含みます。

## 失敗時の確認
フォーカスが見えない場合は:focus-visibleのCSSを確認し、200%拡大でも入力や操作が隠れていないか確認します。

## 演習
色の変化だけで保存結果を伝える方法は十分ですか？

## 解答・確認ポイント
十分ではありません。表示された文字や読み上げ可能な状態通知でも結果を伝えます。
