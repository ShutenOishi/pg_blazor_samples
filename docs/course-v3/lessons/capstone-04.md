# 学習順109：認証済み本人と既存台帳による権限・監査

## 到達目標
AD本人認証とDB既存台帳の認可を区別し、未認証・監査不能で集計を返さないことを検証する。

## 前提と対象業務
第1〜第8段階の内容を使い、架空の課題管理業務を通しで考えます。開発環境はVisual Studio 2026、.NET 10、Blazor Interactive Server、EF Core 10、PostgreSQL 18です。実際のAD/IISは別の実機受入を行います。

## WinForms＋Dapperからの考え方
Active Directoryから利用するのは本人認証とユーザー名だけです。利用者情報を新規登録せず、既存DBの正本ビューから業務権限を判定します。読み取りでも監査の永続化に失敗すれば結果を返しません。

## 実習の操作手順
アプリの `/learn/capstone-04` を開きます。匿名環境で「現在の権限と監査の前提を確認」「認可付き集計を取得する」を実行します。どちらも許可されず集計行が表示されないことを確認します。実認証が成立する環境では正本に有効な権限があり、監査書込み可能な場合だけ業務処理を続行します。

## コードと処理の場所
```csharp
var permit = await Business.AuthorizeAsync();
if (permit.Unit is null) { /* 拒否メッセージ */ }
var result = await Business.CountByDoneAsync();
// 本人・部署を確認し、永続監査が成功した場合のみ集計結果を表示。
```

この抜粋は対応するRazor画面と業務サービスの責任を示しています。Razorのイベントはサーバーで実行されます。**業務データは必ず共通の認可済みサービスでのみアクセス**します。ブラウザーの入力や表示状態を認可の根拠にしてはいけません。

## 拒否・失敗時の確認
学習用画面で本人のログイン名やシークレットを出しません。Cookieや入力欄からユーザー名を自己申告しても認証と認めません。ローカルの学習CIは実AD/Kerberosの受入ではなく、業務DBの安全境界を検証します。

## 確認問題
本人認証は成立しても、既存台帳の権限が無効、または監査DBが停止していた場合はどうなりますか？

## 解答
業務操作を拒否し、一覧・CSV・集計の内容を返しません。
