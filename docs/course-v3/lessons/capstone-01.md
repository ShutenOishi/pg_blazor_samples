# 学習順106：業務要件・画面遷移・WinForms移行の設計

## 到達目標
画面・サービス・DB・認証認可に分割した業務要件と5画面の遷移を説明できる。

## 前提と対象業務
第1〜第8段階の内容を使い、架空の課題管理業務を通しで考えます。開発環境はVisual Studio 2026、.NET 10、Blazor Interactive Server、EF Core 10、PostgreSQL 18です。実際のAD/IISは別の実機受入を行います。

## WinForms＋Dapperからの考え方
WinFormsでは一つのフォームにイベント処理・Dapper SQL・結果表示を集めやすいですが、Interactive ServerではUIの状態とサーバー側の業務認可を区別します。

## 実習の操作手順
アプリの `/learn/capstone-01` を開きます。要件を「部署内一覧」「一件を編集」「部署内CSV」で切り替え、表示される責任分担を確認してください。

## コードと処理の場所
```csharp
private void Explain() => _result = _requirement switch
{
    "list" => "認可された部署内のCountとItemsを一致させる",
    "edit" => "xmin・権限再検査・原子的監査が必要",
    _ => "CSVにも部署範囲・件数上限・監査を適用する"
};
```

この抜粋は対応するRazor画面と業務サービスの責任を示しています。Razorのイベントはサーバーで実行されます。**業務データは必ず共通の認可済みサービスでのみアクセス**します。ブラウザーの入力や表示状態を認可の根拠にしてはいけません。

## 拒否・失敗時の確認
ブラウザーの入力値やURLのIDを権限の根拠にせず、実際に本人認証された主体をサーバー側の業務サービスで扱います。Cookieやcircuitの状態保存は認可の代替になりません。

## 確認問題
画面に編集ボタンが出ないようにすれば、権限のない利用者の編集を防げますか？

## 解答
防げません。操作経路を直接呼ぶ利用者がいることを前提に、必ずサーバー側サービスで編集権限を検査します。
