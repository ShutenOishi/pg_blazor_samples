# 学習順019：URL・履歴・再読込と画面状態

**実装ソース：** [対応するRazor実装](../../../../src/PgBlazorSamples.Web/Components/Lessons/Stage02/L019UrlHistoryStatePage.razor)。画面の正規URLは `/learn/019` です。

## 到達目標
`/learn/019`を操作し、URLに記録される表示条件と、コンポーネントのメモリだけに存在する操作回数を区別します。Webのページはアドレスをコピーでき、戻る・進む・再読込で表示できます。WinFormsではフォームのインスタンス変数を保持する設計が自然でも、WebではURLと画面の一時メモリを分けて扱う必要があります。業務DBの保存や利用者の権限までURLに委ねてはいけません。

学習順017では事前レンダリングと対話型インスタンスの違い、018では編集中の入力と確認済みの値の違いを学びました。今回使うのは一覧と履歴という公開可能な選択肢、および練習用カウンターだけです。Visual Studio 2026、.NET 10、ChromeのInteractive Server環境で確認し、ADやPostgreSQLには接続しません。

## URLのクエリ文字列はどう使われるか
画面の `Tab` プロパティには `[SupplyParameterFromQuery(Name = "tab")]` が付いています。この指定により、`?tab=history` といったクエリ文字列の値をコンポーネントへ渡せます。`NavigationManager`を注入した `Navigation` は画面遷移に使います。「履歴をURLで選ぶ」を押すと、ページURLは `/learn/019?tab=history` になります。表示は `Tab == "history"` の場合に「履歴」、それ以外の場合に「一覧」となります。

```csharp
@inject NavigationManager Navigation

[SupplyParameterFromQuery(Name = "tab")]
[Parameter] public string? Tab { get; set; }
private int count;

// URLには公開可能な表示条件だけを含める。
private void Choose(string value)
    => Navigation.NavigateTo($"/learn/019?tab={value}");

private void Increase() => count++;
```

このコードは `NavigateTo` を使うだけで、DBへの問い合わせや履歴レコードの登録を行っていません。ブラウザー履歴と業務アプリの「履歴一覧」は異なる概念です。ここでいう履歴は表示タブの名称であって、永続的な監査ログではありません。`Tab` の値はURLから読み取れる一方、`count` は現在のコンポーネントのフィールドであり、URLには含まれません。

画面がどちらを表示するかは次の条件式で決まります。

```razor
<p>選択中の表示：
    <strong data-testid="runtime04-tab">
        @(Tab == "history" ? "履歴" : "一覧")
    </strong>
</p>
<button type="button" @onclick='() => Choose("list")'>
    一覧をURLで選ぶ
</button>
<button type="button" @onclick='() => Choose("history")'>
    履歴をURLで選ぶ
</button>
<p>操作回数：
    <strong data-testid="runtime04-count">@count</strong>
</p>
<button type="button" @onclick="Increase">操作回数を1増やす</button>
```

`Increase` が実行されると `count` が1増えて再描画されます。しかし `Navigation.NavigateTo` は呼ばれず、URLは変わりません。同じコンポーネントが生きている間は回数が維持されますが、ページを再読込して新しいインスタンスが作られた場合には初期値0へ戻ります。URLに残った `tab=history` は改めて読み取られるため、表示条件だけは再現できます。

## WinForms＋Dapperとの比較
| WinFormsでの経験 | 今回のWebの仕組み | 重要な違い |
| --- | --- | --- |
| Formのフィールド | count | 現在のインスタンスだけの一時値で、再読込時には失われる |
| 画面の選択状態を起動引数で渡す | URLの?tab=history | コピー・共有・ブックマークができる |
| 前に開いたフォームへ戻る | ブラウザーの戻る・進む | URLの履歴とメモリ状態は同じではない |
| Dapperで閲覧履歴を記録 | この画面にはない | タブ名「履歴」はDBの監査履歴ではない |
| ローカル設定へ保存 | 必要に応じて別の保存先 | 表示条件の再現と永続保存を区別する |

ブラウザーの履歴は、過去に訪れたURLを再訪するための仕組みです。サーバーのメモリ上の操作回数やDBの更新内容をすべて巻き戻す機能ではありません。対話型のナビゲーションによって同じコンポーネントが保持される場合もあるため、ページ移動時に必ず一律の回数へ戻るという説明は避け、再読込で新しいインスタンスを確かめるのが確実です。

## 操作手順
1. `/learn/019` を開き、表示が「一覧」、操作回数が0であることを確認します。
2. 「履歴をURLで選ぶ」を押し、アドレス欄の `?tab=history` と画面の「履歴」表示を見比べます。
3. 「操作回数を1増やす」を二度押します。画面が2になったこととURLが変化していないことを確認します。
4. Chromeの再読込を実行します。アドレスに `tab=history` が残り、画面は「履歴」ですが、操作回数は0へ戻るはずです。
5. 「一覧をURLで選ぶ」を押してURLの値を `list` に変えます。戻るで `tab=history` と「履歴」、進むで `tab=list` と「一覧」へ戻ることを確かめます。この間の一時カウントは画面の再生成方法に左右されるため、履歴と同じ値へ巻き戻るとは判定しません。
6. `/learn/019?tab=history` を直接開いて「履歴」を確認し、`/learn/019?tab=admin` を直接開いた場合は「一覧」にしかならないことを確かめます。URLをコピーして新しいタブに貼り付けても、再現されるのは公開可能な表示条件だけです。

## URLへ置いてよい情報、置けない情報
URLに含める候補は、公開して差し支えない画面のタブ名、ページ番号、並べ替え条件などです。検索語であっても個人情報を含む場合があります。URLは履歴やログ、コピー先、場合によっては参照元情報として残るため、機密性を考えて選んでください。パスワード、認証Cookie、アクセス権限を示す値、業務上の秘密は入れません。

また、`tab=history` は利用者が自由に変更できます。仮に `tab=admin` と書いても管理者の権限を与えてはいけません。表示条件と業務の認可は別です。後続の業務画面では、ADが認証した本人のドメインユーザー名を使い、事前に整備された既存DB・外部台帳で都度認可します。URLにある部署番号やタブ名だけを信用してDBの閲覧・更新対象を広げないようにします。

## 障害の切り分け
| 症状 | 最初に調べる箇所 | 判断 |
| --- | --- | --- |
| 再読込でcountが0になった | countフィールドと初期値 | DB保存がなければ期待どおり |
| 履歴ボタンを押しても一覧と表示される | URLのtabとTabの値 | クエリ名、値、再描画を確認 |
| 戻るボタンでcountまで復元されると思った | 履歴と状態の違い | ブラウザー履歴はアプリの完全なスナップショットではない |
| HTMLは見えるが選択ボタンが動かない | SignalRとサーバーログ | Document成功と対話型イベントは別 |
| URLに秘密情報が入っていた | パラメーターの設計 | 履歴・ログへ残るため取り扱いを改める |
| URLの文字を変更すると権限が変わる | サーバー側の認可処理 | 表示条件から権限を導く設計は不適切 |

切り分けでは、まずアドレス欄、次に画面の表示、最後にサーバーのイベント処理を順に確認してください。URLはブラウザー側にも残りますが、Interactive ServerのC#フィールドとは別の場所です。通信不調ならNetworkとConsole、サーバーログも調べます。

## 演習と詳しい解答
**演習A：** 履歴を選び、操作回数を2にして再読込したときの表示を予想してください。

**解答A：** URLの `tab=history` は残るので表示条件「履歴」は再現します。一方、`count` はコンポーネントの一時フィールドだけで、再読込後に初期値0から始まります。`SupplyParameterFromQuery` と通常のフィールドが違う役割であることを確認できます。

**演習B：** URLに `?tab=admin` と入力しただけで管理者向けの業務データを返す設計は安全でしょうか。

**解答B：** 安全ではありません。URLは利用者が編集できるため、本人の権限根拠にはなりません。今の実装では `history` 以外は一覧表示になるだけで、実DB処理はありません。実業務ではサーバーが認証済み本人と既存台帳を照合し、対象の部署・業務単位でアクセスを拒否または許可します。

**演習C：** フォームの一時入力をURLにすべて入れれば、再読込対策として十分でしょうか。

**解答C：** 不適切な場合があります。URLは共有・記録され、長さにも実用上の制約があります。秘密の値や個人情報を含む入力はURLへ置けません。短期の一時状態、公開可能な表示条件、永続化が必要な業務データを分けて保存先を選びます。次の学習順020でcircuit、ブラウザー、DBを比較します。

## 完了条件と次の学習
表示条件と操作回数のどちらが再読込後に残るかを、実際のコードとURLから説明できれば完了です。URLは公開可能な画面条件を表現する手段であり、永続化や認可の代わりではありません。学習順020では、画面の一時状態、ブラウザーの設定、業務DBへの記録のうち適切な保存先を選びます。
