# 学習順015：SignalR・circuit・再接続

## 学習の目的
SignalR・circuit・再接続を、WinFormsのイベント処理と比較しながら理解します。ここではWebサーバー上のC#とブラウザーの表示を区別します。

## 前提と動作環境
学習順001〜014で学んだHTTP、HTML、Razorの基本を使います。.NET 10のInteractive Serverを前提とし、DB/ADは使いません。

## 画面で確かめること
`/learn/runtime-02`を開いてください。回数を増やしてからブラウザーを再読込し、値が初期状態に戻ることを確認する。

## 動作と処理場所
SignalRは通信経路、circuitはサーバーの対話状態です。再接続できても状態の保持は常に保証されません。ページを再読込すると新しい状態になる場合があります。

## 主要なC#コード
```csharp
private int count;
// サーバー上の画面状態を操作する。永続保存はしない。
private void Increase() => count++;
```
Razorの `@onclick` が上のC#メソッドを呼び出します。完成画面を操作しながらRazorの表示とC#メソッドを確認してください。

## WinForms・Dapper経験者が注意する点
WinFormsではフォーム上の変数がPCのプロセスで維持されます。Interactive Serverでは画面状態がサーバーの対話回線と結び付き、ブラウザーやDBに自動保存されるわけではありません。

## よくある失敗と確認方法
画面が動かない場合はブラウザーのNetworkとConsole、サーバーのログ、再接続の案内を確認してください。表示されているHTMLだけでサーバー側処理の成功を判断しないでください。

## 演習と解答
**演習：** 回数を増やしてからブラウザーを再読込し、値が初期状態に戻ることを確認する。

**解答：** circuitの状態は永続化されたデータではありません。復元の必要な情報は別の保存先へ置きます。
