# 学習順020：circuit・ブラウザー・DBの状態保存の選択

## 学習の目的
circuit・ブラウザー・DBの状態保存の選択を、WinFormsのイベント処理と比較しながら理解します。ここではWebサーバー上のC#とブラウザーの表示を区別します。

## 前提と動作環境
学習順001〜019で学んだHTTP、HTML、Razorの基本を使います。.NET 10のInteractive Serverを前提とし、DB/ADは使いません。

## 画面で確かめること
`/learn/runtime-05`を開いてください。利用者の権限情報をブラウザーの保存領域だけに置いて判定してよいか考える。

## 動作と処理場所
circuitのメモリ・ブラウザーストレージ・DBでは保存できる期間と信頼性が異なります。画面は保存先の判断を練習するもので、ブラウザーやDBへの保存はしません。

## 主要なC#コード
```csharp
private string selected = "circuit";
// 保存先の候補を説明する。実際の保存処理は行わない。
private void Select(string value) => selected = value;
```
Razorの `@onclick` が上のC#メソッドを呼び出します。実装は `src/PgBlazorSamples.Web/Components/Samples/Runtime/Runtime05Page.razor` と対応しています。

## WinForms・Dapper経験者が注意する点
WinFormsではフォーム上の変数がPCのプロセスで維持されます。Interactive Serverでは画面状態がサーバーの対話回線と結び付き、ブラウザーやDBに自動保存されるわけではありません。

## よくある失敗と確認方法
画面が動かない場合はブラウザーのNetworkとConsole、サーバーのログ、再接続の案内を確認してください。表示されているHTMLだけでサーバー側処理の成功を判断しないでください。

## 演習と解答
**演習：** 利用者の権限情報をブラウザーの保存領域だけに置いて判定してよいか考える。

**解答：** できません。改ざん可能なクライアント情報を認可の正本にせず、サーバー側の既存台帳を都度確認します。
