# 学習順020：circuit・ブラウザー・DBの状態保存の選択

**実装ソース：** [対応するRazor実装](../../../src/PgBlazorSamples.Web/Components/Samples/Runtime/Runtime05Page.razor)。画面の正規URLは `/learn/020` です。

## 到達目標と前提
`/learn/020`で、画面の一時状態、公開してよい表示設定、複数端末で共有する業務データの保存先を選びます。WinForms＋Dapperでの経験を基に考えると、Formフィールド、ローカル設定、DBの三つを使い分けた場面が対応します。しかしBlazorのInteractive Serverはサーバーでコンポーネントの状態を持ち、ネットワークとcircuitの寿命に依存します。デスクトップのフォームと同じ期間保持されると考えないでください。

この画面は選択結果を説明するほか、機密性のない表示設定をlocalStorageへ保存し、再読込後に取得する教材です。PostgreSQLへ接続するコードはありません。「データベース」を選ぶボタンはDB保存の実行ボタンではありません。学習順015のSignalR、016の破棄、017の事前レンダリング、018の入力検証、019のURLの知識をまとめます。実ADやIISの検証は行いません。

## 保存先の違いを先に整理する
Interactive Serverのコンポーネントは、一時的な文字列やカウンターをC#のフィールドへ保持できます。この値はサーバー側の現在のインスタンスに結び付きます。同じcircuitへ再接続できた場合は残る可能性がありますが、サーバーの再起動、再読込、保持期間の経過などで失われることがあります。長期間保持すべき業務記録には向きません。

ブラウザーのストレージには、端末側に残してよいUI設定などを保存する選択肢があります。ただし利用者自身が変更・削除でき、端末によって内容が違います。保存できたとしても、その値は本人確認や業務権限の証拠にはなりません。例えばダークモードなどの機密性のない設定を保存することは考えられますが、「利用者は管理者である」というフラグを保存してDB更新許可の根拠にすることはできません。

データベースは継続的に管理する業務レコードの保存先です。DapperやEF CoreからDBへ書き込む処理が必要で、認証済み本人、既存DB台帳に基づく都度認可、更新競合、トランザクション、永続監査の条件を満たす必要があります。保存先をDBにしただけでこれらの要件が自動成立するわけではありません。DBについては保存先の選定だけを学びます。ブラウザーの保存例は非機密の表示設定に限ります。

## 実際のRazorとC#を読む
```razor
<button type="button" @onclick='() => Select("circuit")'>
    画面の一時状態
</button>
<button type="button" @onclick='() => Select("browser")'>
    公開できる表示設定
</button>
<button type="button" @onclick='() => Select("database")'>
    業務の永続データ
</button>
```

ボタンは `Select` というメソッドを呼ぶだけです。画面で保存先の種類を選択しても、実際の永続化は行われません。選択した文字列から表示文を切り替えるコードが以下です。

```csharp
private string selected = "circuit";

// 保存先の候補を説明する。実際の保存処理は行わない。
private void Select(string value) => selected = value;
```

```razor
<p data-testid="runtime05-choice">@(selected switch
{
    "browser" => "候補：ブラウザーの保存領域。ただし改ざん可能で、認可の根拠にはできません。",
    "database" => "候補：データベース。認証済み本人と権限をサーバーで検証して保存します。",
    _ => "候補：circuit上の状態。切断や再起動で失われる可能性があります。"
})</p>
```

`selected` そのものもサーバー側の一時フィールドです。つまり「ブラウザー」を押したからといって、その選択がブラウザーのストレージへ保存されるわけではありません。「DB」を押してもINSERT、UPDATE、SaveChangesは呼ばれません。このコードの作用を正しく読めることが大切です。画面に表示された説明を処理成功の証跡と混同してはいけません。

## 非機密のブラウザー保存を実行する

学習順020のRazorでは、`comfortable`（標準）と`compact`（コンパクト）だけを値として認め、JavaScript interopを介して`localStorage`へ書き込みます。保存値はブラウザー側で変更できるので、読み戻し時にも許可リストで検査します。実データ・認証トークン・権限・接続文字列は保存しません。

```csharp
private const string DisplaySettingStorageKey = "pgblazor-course-runtime05-display";
private async Task SaveDisplaySettingAsync()
{
    if (displaySetting is not ("comfortable" or "compact"))
    {
        browserStatus = "許可されていない表示設定です。";
        return;
    }
    try
    {
        await JS.InvokeVoidAsync("localStorage.setItem", DisplaySettingStorageKey, displaySetting);
        browserStatus = "非機密の表示設定を保存しました。";
    }
    catch (JSException)
    {
        browserStatus = "ブラウザーに保存できませんでした。";
    }
}
```

```csharp
var stored = await JS.InvokeAsync<string?>("localStorage.getItem", DisplaySettingStorageKey);
if (stored is "comfortable" or "compact")
{
    displaySetting = stored;
    browserStatus = "ブラウザーから表示設定を読み込みました。";
}
else
{
    browserStatus = "保存データがないか、許可されない値です。";
}
```

正規URL `/learn/020` を開き、「公開できる表示設定」ボタンの選択結果が画面へ反映されてから、表示の好みで「コンパクト」を選択してください。画面内の「C#が受け取った表示設定：compact」が更新されたことを確認してから保存、ページを再読込、読み込みを実行してください。SSR表示直後はブラウザーのselect要素だけが変化しても、Interactive Serverの`@bind`イベントがまだC#へ届いていない場合があります。選択値が復元される一方、候補説明の状態は初期化されます。利用者がlocalStorageを削除または任意の値に改ざんした場合は、許可されない値を表示設定へ取り込みません。Chrome操作テストは保存→再読込→復元を自動検証します。

## WinForms＋Dapperとの比較
| WinForms＋Dapperの経験 | Blazorでの候補 | 保持期間と注意点 |
| --- | --- | --- |
| Form内の一時変数 | コンポーネントのフィールド | circuitやインスタンスの寿命に依存する |
| アプリのローカル設定 | ブラウザーストレージ | 利用者が改ざん可能。機密データや業務認可の根拠には不適切 |
| 一覧画面の選択タブ | URLのクエリ | 公開可能な条件なら再読込・共有で再現できる |
| Dapper.ExecuteとDB | PostgreSQLなどの業務DB | 本人認証、既存台帳認可、競合、監査が必要 |
| 全フォーム共有の静的変数 | Singleton等の共有状態 | 利用者間で混ざる危険があるため個人の秘密を保持しない |

この比較は保存先の性質を理解するためのものです。ブラウザーストレージにはsessionStorageとlocalStorageなど保存期間の違う選択肢があり、実際に利用するにはブラウザー側APIとの連携が必要です。今回の画面ではlocalStorageへの保存と再取得を操作できます。業務システムでは、多人数・複数端末・長期保存・権限失効が重なるので、何をどこへ保存するかを要件として明記します。

## 実際の操作手順
1. `/learn/020`へアクセスし、最初に表示されるcircuitの説明を読みます。一時状態に永続性がないことを確認します。
2. 「公開できる表示設定」を押します。「ブラウザーの保存領域」「改ざん可能」「認可の根拠にはできません」の文言を確認します。
3. 「業務の永続データ」を押し、本人と権限をサーバーで検証して保存する必要がある説明を読みます。ボタンによって実際のレコードは作られていません。
4. 「画面の一時状態」を押して最初の候補に戻します。画面の文字が変わるのは `selected` の切替結果です。
5. 「コンパクト」を選び、C#が受け取った値も`compact`と表示されたのを確認してから「表示設定をブラウザーへ保存する」を押します。再読込後に「ブラウザーから表示設定を読み込む」を押し、「コンパクト」が復元されることを確かめます。候補選択の一時状態は再読込で戻ります。DBへの保存は行いません。
6. 第4組の復習 `/learn/column/runtime-20` を開き、これまでの5画面の値がどこに保持されるか説明してください。

## 状態の種類と選び方
| データの性質 | 第一候補 | 追加で確認する条件 |
| --- | --- | --- |
| 一度だけ押したカウンター | circuitの一時フィールド | 切断時に失われてもよいか |
| 公開可能な一覧タブ | URL | コピーやアクセスログに残ってもよいか |
| 端末の配色設定 | ブラウザーストレージ | 端末ごとに違ってもよいか |
| 申請書の確定済み内容 | 業務DB | 本人認証、権限、競合、監査、復旧が必要 |
| 利用者の業務権限 | サーバー側の既存台帳照合 | クライアント値では認可しない |
| 監査対象の更新結果 | DB内の永続記録など | 更新と監査の原子性、失敗時の拒否を確認 |

運用時には、データの機密性、改ざんの可能性、保存期間、複数端末での同期の要否を一つずつ確認します。circuitは永続的な利用者セッションの保証ではありません。特にADの本人確認を維持するCookieと、画面の一時値を混同しないでください。業務データを更新するときはその場で権限を判定し、古い画面の表示やキャッシュから許可を推定しません。

## 障害の切り分け
| 症状 | 最初に調べる場所 | 結論と対応 |
| --- | --- | --- |
| 「DB」を押してもレコードが増えない | Selectのコード | 候補説明だけの切替なので正常 |
| 候補選択が再読込で戻った | selectedフィールド | 候補選択は一時状態。別の表示設定だけをlocalStorageへ保存する |
| 接続を失ったらカウンターが消えた | circuitとインスタンス寿命 | 永続化していない値は復元保証がない |
| localStorageの値が無い・不正 | 保存領域の初期化や利用者による変更 | UI設定だけを検証し、値を信用した認可を行わない |
| HTMLは表示されるがボタンが反応しない | SignalR、Network、サーバーログ | 対話型接続と静的HTMLを区別 |
| Dapperの値と表示が食い違う | 実際のDB読書き処理の有無 | この画面ではDBに接続していない |

## 現実の業務システムでの注意
10,000人以上が利用するシステムでも、各人の一時状態をサーバーの無制限な共有メモリへ積み上げる設計は適切とは限りません。接続ごとの資源、失効、再接続、スケールアウトを検討する必要があります。ただし現段階では負荷試験も実IIS・Kerberos受入も実施していません。設計上の条件と実機検証の完了は分けて記録します。

事前に整備された既存DBまたは外部台帳を権限の正本として使用し、ADからは本人の認証とドメイン付きユーザー名だけを利用する方針です。FDWや別DBをまたぐ書込みで原子性が証明できない場合は、更新と監査が同時に保証されたと主張せず安全に拒否する必要があります。`application_name` は補助的な診断情報であって、個人監査の代用品ではありません。

## 演習と詳しい解答
**演習A：** 公開できる画面タブ、入力途中の一時文字列、共有する業務データ、利用者の業務権限をそれぞれどこへ置くか考えてください。

**解答A：** 公開可能なタブはURL、短期の入力はcircuit内のフィールド、複数端末で確定結果を共有する業務データは権限確認を伴うDBが候補です。業務権限はブラウザーストレージへ置いた値を正本とせず、認証済み本人と事前整備された既存DB・外部台帳をサーバー側で照合します。用途と機密性によって判断します。

**演習B：** 「業務の永続データ」ボタンを押した直後ならDBへ保存されたと説明できますか。

**解答B：** できません。Selectはselectedという文字列を変更し、説明文を切り替えるだけです。DB接続、INSERT、SaveChanges、トランザクション、監査はこのコードに存在しません。保存が成功したと表示するには、実際の処理結果を確認する必要があります。

**演習C：** ブラウザーに保存した「管理者=true」があるため、サーバー側の業務認可を省略できますか。

**解答C：** できません。クライアント側の値は利用者が変更可能であり、本人や権限の証拠になりません。サーバー側の既存台帳による都度認可が必要です。表示できることと、業務データを読み書きする権限があることを分けてください。
