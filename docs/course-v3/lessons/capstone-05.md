# 学習順110：E2E・障害復旧・IIS受入表

## 到達目標
Unit/xUnit・PostgreSQL18結合試験・Chrome実操作・Windows Server 2025/IIS/ADの実機受入を分ける。

## 前提と対象業務
第1〜第8段階の内容を使い、架空の課題管理業務を通しで考えます。開発環境はVisual Studio 2026、.NET 10、Blazor Interactive Server、EF Core 10、PostgreSQL 18です。実際のAD/IISは別の実機受入を行います。

## WinForms＋Dapperからの考え方
CIのSUCCESSは自動テストの範囲に対する証拠です。IIS・Kerberos/SPN・HTTPS証明書・Data Protection鍵の共有・実際の1万人規模負荷・障害復旧は現地で別に確認します。

## 実習の操作手順
アプリの `/learn/capstone-05` を開きます。4項目のチェックリストを順に選び「受入の不足を確認する」を押してください。すべて選択しても、画面だけでは本番受入を証明しないメッセージが残ることを確認します。

## コードと処理の場所
```csharp
// チェックは受入観点の自己点検にとどめる。
_status = missing.Count > 0
    ? "受入に不足：" + string.Join("、", missing)
    : "自己点検のみ。独立した実機証跡が必要です。";
```

この抜粋は対応するRazor画面と業務サービスの責任を示しています。Razorのイベントはサーバーで実行されます。**業務データは必ず共通の認可済みサービスでのみアクセス**します。ブラウザーの入力や表示状態を認可の根拠にしてはいけません。

## 拒否・失敗時の確認
暗黙にCIからIISやADの実機成功を宣言しません。切戻し手順、Cookieの復号不能、鍵喪失、監査書込み障害、データ更新の二重実行、DB障害時のフェイルクローズを個別に受入します。

## 確認問題
Windows/Linux・Chrome・PostgreSQL18のCIがすべて成功したら、AD統合とIISの本番移行を承認できますか？

## 解答
できません。Kerberos、証明書、鍵共有、負荷、障害復旧の実機証跡が別に必要です。
