# 学習順108：DTO編集・競合・取消・例外の統合

## 到達目標
詳細DTOを読み込み、フォーム入力・取消・保存直前認可・xmin競合を一連の操作として扱う。

## 前提と対象業務
第1〜第8段階の内容を使い、架空の課題管理業務を通しで考えます。開発環境はVisual Studio 2026、.NET 10、Blazor Interactive Server、EF Core 10、PostgreSQL 18です。実際のAD/IISは別の実機受入を行います。

## WinForms＋Dapperからの考え方
WinFormsのDataGridViewから選択して編集する流れを、Blazorの表示DTO・フォーム・サービスに分けます。保存はDB権限に基づいて行い、以前見えたことだけで保存を許しません。

## 実習の操作手順
アプリの `/learn/capstone-03` を開きます。番号を指定して「認可付き詳細を取得する」を押し、取得できた場合だけ名称・完了を変更します。取消ではDBを書き換えません。保存時はSecuredLearningServiceが本人・部署・編集許可とxminを検査し、監査を同一トランザクションで確定します。匿名時は拒否され編集フォームは表示されません。

## コードと処理の場所
```csharp
var detail = await Business.GetDetailAsync(id);
// 認可された詳細があった場合だけ、読込時の版を渡して保存する。
var result = await Business.SaveAsync(new LearningEditInput {
    Id = detail.Item!.Id, Version = detail.Item.Version,
    Title = title, IsDone = isDone
});
// Conflict/Forbidden/Errorでは古いDTOを保持しない。
```

この抜粋は対応するRazor画面と業務サービスの責任を示しています。Razorのイベントはサーバーで実行されます。**業務データは必ず共通の認可済みサービスでのみアクセス**します。ブラウザーの入力や表示状態を認可の根拠にしてはいけません。

## 拒否・失敗時の確認
無効な課題番号、0文字/101文字以上の入力、競合、権限変更、監査失敗は別の理由です。編集DTOを保持したまま再送せず、競合・拒否時には再読み込みを要求します。FDW先の監査の原子性が保証できない場合は更新を拒否します。

## 確認問題
画面を表示した後で編集権限を失った場合、編集内容は保存されますか？

## 解答
されません。保存時に台帳の正本を再確認し、ロック・競合・監査が成立しない場合は拒否します。
