# 学習順002：URL・HTTPの要求と応答を理解する

## 到達目標

学習順001では、Interactive Serverのボタン操作をサーバー上のC#が処理することを確認しました。しかし、ボタン操作より前に、ブラウザーはどのようにページの存在を知るのでしょうか。このステップでは、**URL・HTTP要求・HTTP応答・ステータスコード**を整理し、Webページの初回取得と対話型イベントの通信を区別します。

WinFormsのフォームを開く処理では、通常はローカルのクラスやアセンブリの参照を意識します。Webでは利用者がURLを指定し、ブラウザーがWebサーバーへ要求を送ります。画面を開くための\`GET\`と業務データを変更する要求を同一視しないことが重要です。

## 1. URLを分解して読む

教材では、開発中の実行環境が表示したホスト名とポート番号に、\`/learn/web-02\`を付けてアクセスします。例えば開発者の端末で\`https://localhost:5001/learn/web-02\`と表示された場合、各部分には意味があります。**ポート番号は例示**であり、実際の起動設定に従ってください。

| 部分 | 例 | 意味 |
| --- | --- | --- |
| スキーム | \`https\` | 通信方式。HTTPSはTLSで通信経路を保護 |
| ホスト | \`localhost\` | 接続先のホスト名。開発時は自PCを示す |
| ポート | \`5001\` | 同じホストのどの待受先かを示す |
| パス | \`/learn/web-02\` | アプリ内の対象ページを示す |
| クエリ | \`?page=2\` | 必要に応じて付ける検索条件など |
| フラグメント | \`#example\` | 主に文書内の場所を指定する |

この教材の実際の画面は\`@page "/learn/web-02"\`でパスを宣言します。ユーザーがURLを指定したとき、ルーティングにより対応するRazorコンポーネントが選ばれます。

## 2. HTTPで何を送受信するか

ブラウザーがページを開くと、典型的には次のようなHTTP要求と応答のやり取りが生じます。以下は**仕組みを説明するための簡略例**であり、実際のヘッダーやステータスは実行環境で異なります。

\`\`\`http
GET /learn/web-02 HTTP/1.1
Host: localhost:5001
Accept: text/html
\`\`\`

\`\`\`http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!DOCTYPE html>
<html lang="ja">...</html>
\`\`\`

実際の通信では、ブラウザーはHTMLだけでなくCSS、JavaScript、画像などのリソースも必要に応じて取得します。Networkに複数の要求が並ぶのは正常です。また、\`200\`以外にも応答の目的や状況に応じたステータスが存在します。

| HTTPメソッド・応答 | 代表的な用途 | この段階での注意 |
| --- | --- | --- |
| GET | ページやリソースの取得 | 再読み込みでNetworkのDocumentを確認 |
| POST | フォーム・データの送信 | すべてのクリックがPOSTではない |
| 200 | 要求が成功した | アプリ内の業務成功とは同義ではない |
| 302 | 一時的なリダイレクト | ログイン先などへの遷移が生じる場合もある |
| 400 | 不正な要求 | 入力やHTTPの形式・検証を確認 |
| 401 | 認証が必要 | 本人認証が成立していない場合がある |
| 403 | 要求を禁止 | 認証済みでも操作を許されない場合がある |
| 404 | リソースが見つからない | URLやルートが正しいか確認 |
| 500 | サーバー内部エラー | サーバー側のログで原因を調べる |

HTTPが200だったからといって「DB書込みに成功した」「認可された」と判断することはできません。後のステップでサーバー側の検証を追加します。

## 3. 画面にあるC#コードを読む

実装ファイル\`Web02Page.razor\`には、現在のパスを確認する次のコードがあります。

\`\`\`razor
@page "/learn/web-02"
@inject NavigationManager Navigation

<p>現在のパス：
    <strong data-testid="web02-path">@CurrentPath</strong></p>

@code {
    private string CurrentPath => new Uri(Navigation.Uri).AbsolutePath;
}
\`\`\`

\`NavigationManager\`は現在のナビゲーション情報を扱うBlazor標準の仕組みです。\`@inject\`は、DIコンテナーに登録されているサービスをコンポーネントへ渡します。DIの内部構造は第3段階で詳しく学ぶため、ここでは「URLを自分で解析するために新しいWebブラウザーを起動しているわけではない」という点を理解すれば十分です。

\`Navigation.Uri\`は完全なURLを返し、\`new Uri(...).AbsolutePath\`はそのパス部分を取り出します。ブラウザーで\`/learn/web-02\`を開くと、画面にはその文字列が表示されます。

## 4. Interactive Serverの通信との違い

学習順001のクリックは通常のフォームPOSTであるとは限りません。この教材では\`App.razor\`に次の指定があります。

\`\`\`razor
<HeadOutlet @rendermode="InteractiveServer" />
<Routes @rendermode="InteractiveServer" />
<script src="@Assets["_framework/blazor.web.js"]"></script>
\`\`\`

\`InteractiveServer\`の対話処理では、Blazorがブラウザーとサーバーの通信経路を管理し、利用可能な環境ではSignalRのWebSocketなどを使用します。通常のDocument GETと、接続確立後の対話イベントをNetworkで別に観察してください。特に**HTTPの再読み込みを一回行ったからといって、すべてのボタンクリックが毎回ページ全体の取得になるわけではありません**。

## 5. ブラウザーでの実習

1. アプリの\`/learn/web-02\`を開き、画面に「現在のパス：/learn/web-02」と表示されることを確認します。
2. ブラウザーの開発者ツールを開き、Networkを選びます。
3. Networkの記録を消去し、ページを再読み込みします。
4. 種類が\`Document\`の要求を選び、MethodがGETであること、要求URLと応答のStatusを確認します。
5. \`_framework/blazor.web.js\`などの追加リソースと、Document要求が別の項目になっていることを確認します。
6. 学習順001へ戻ってボタンを押し、Networkにどの通信が現れるかを観察します。WebSocketのタブがある場合は、対話型接続の存在も確認します。

開発者ツールの名称や並びはChrome/Edgeの版によって変わることがあります。Networkから実際の通信を見て、表示上の推測だけで判断しないでください。

## 6. WinFormsでのDapperアクセスとの関係

WinFormsからDapperを使ってPostgreSQLへ直接接続する場合、画面プログラムがDB接続文字列を直接扱う構造になることがあります。一方、この教材の本番想定では、**ブラウザーからPostgreSQLへ直接接続するのではなく**、サーバー側のC#が認可済みのサービスを使ってDBを操作します。ブラウザーへ接続文字列やパスワードを返してはいけません。

| 観点 | WinFormsからDBを利用 | 本教材のWebアプリ |
| --- | --- | --- |
| DBへ接続する処理 | クライアントアプリが担う設計もある | Webサーバー側のサービス |
| 表示更新 | コントロールへ値を反映 | ブラウザーのHTMLが更新される |
| 認証・認可 | Windowsログオンとアプリの権限を設計 | サーバー側で現在の本人・既存DB台帳を照合 |
| 機密情報 | クライアントに含めない工夫が必要 | ブラウザーへ秘密を送らずサーバー側で管理 |

この段階の\`web-02\`画面自体はDBへの接続・認証を行いません。

## 7. 失敗時の切り分け

| 観察 | 考えられる範囲 | 次にすること |
| --- | --- | --- |
| Documentが404 | URLのパスに対応するページがない | \`@page\`の値・URLを確認 |
| Documentの要求自体がない | ブラウザーのキャッシュや記録条件など | Networkを開いたまま再読み込みする |
| Documentは200、クリックが動かない | 対話型接続やC#イベントの問題 | Consoleと接続要求、サーバーログを確認 |
| HTTPSの証明書警告 | TLS証明書の信頼関係 | 開発証明書・HTTPS設定を確認。警告は安易に無視しない |
| 画面に401/403 | 認証設定やアクセス権の違い | サーバー側の認証・認可設定を確認 |

## 8. 演習と解答

**問1：** \`https://localhost:5001/learn/web-02\`のパスは何ですか。

**解答：** \`/learn/web-02\`です。ホストやポートはパスに含みません。

**問2：** NetworkでDocumentのGETが200だった場合、業務更新の成功も意味しますか。

**解答：** 意味しません。200はそのHTTP要求が成功したことを表し、別の業務処理の認可やDB更新を証明しません。

**問3：** Blazorのボタン操作が通常のHTTP POSTと同一でないのはなぜですか。

**解答：** この教材はInteractive Serverを使用し、Blazorが管理する対話型接続でイベントがサーバーへ届けられるためです。
