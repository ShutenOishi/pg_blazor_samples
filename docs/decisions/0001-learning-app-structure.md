# ADR-0001：基本は単一の学習用Blazor Webアプリを拡張する

- 状態：採用予定
- 記録日：2026-10-26
- 対象：学習教材の構成

## 背景

初級から上級まで数十個のサンプルを作る。各ステップを完全独立アプリにすると、プロジェクト、起動設定、NuGet、認証、画面レイアウトの重複が増え、更新負荷と学習開始時の手間が大きくなる。

## 決定

1. `PgBlazorSamples.Web`を基本ホストとし、`Components/Samples/StepNN`単位で題材を分ける。
2. ステップごとに固有URL、目次、前提、操作方法、演習、完了条件を持つ。
3. 共通のMudBlazor初期化、DI、セキュリティ、DBアクセスを使う。学習目標を示す場合に限り専用コードを置く。
4. 外部依存（DB/AD）がないステップを先に完成させる。
5. 独立実行しなければ教育上の意味がないテーマだけ別プロジェクトとする。

## 想定するトレードオフ

- 利点：メンテナンスが容易、共通変更を一括で検証できる、ステップ間の回遊がしやすい。
- 欠点：すべての学習ステップが同じ実行ホストの変更影響を受ける。段階ごとの途中完成状態を再現するには必要に応じGitタグや差分の解説を用意する。

## 再検討条件

学習ステップに必要な設定が矛盾する、複数の異なる認証ホストが必要になる、初学者に不要な依存が明らかに大きくなるなどの具体的な問題が発生したら再検討する。
