# ステップ67：部署ごとのCountとItems

## 到達目標

同一のWHEREを使った行レベル制御を実行例で理解します。Visual Studio 2026、.NET 10、MudBlazor、EF Core 10、PostgreSQL 18を用います。

## このステップで学ぶこと

既存台帳のunit_codeを権限範囲に用います。検索結果の総件数と一覧の行を、同じ部署条件から求めます。

## 画面の操作

1. ステップ67で「認可付き一覧を取得する」を押す。
2. 匿名なら行・総件数の両方が0件のまま拒否されることを確認する。
3. 実DBテストでは、自部署と他部署の架空課題を混在させ、自部署の1件だけを取得する。

## C#とSQLのしくみ

Visible(db, unit)が業務クエリの起点です。Count、Items、詳細、集計、CSV、保存が同じunit_codeを使用します。単に画面のRowsだけをフィルターするとTotalCountから情報が漏れます。

## 安全性と境界

業務用の利用者登録機能は作りません。認可の正本は管理者が構成する既存テーブル/外部テーブルを表す読み取り専用ビューです。匿名・権限なし・DB障害では拒否し、データやSQL結果を出しません。

実AD/IIS/Kerberosの認証成功はCIでは代替できません。業務で使う場合は実環境の接続方式・本人・権限更新・監査を別途受け入れてください。

## 確認問題と解答

**Q. 実データの一覧に全社のTotalCountを返してよい？** いいえ。所属・検索条件を同一にします。
