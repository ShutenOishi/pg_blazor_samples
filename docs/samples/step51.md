# ステップ51：編集フォームとDTO

## できるようになること

一覧の行を選択して、DBから読み直した入力DTOを検証して保存する。 Visual Studio 2026、.NET 10、Blazor Interactive Server、MudBlazor 9、EF Core 10、開発用PostgreSQL 18を使用します。

## 前提条件

Step31〜50のDbContextFactory、CRUD、ServerData、楽観的排他を学んだ後に進みます。DB未設定の場合は実操作できず、日本語の設定案内を表示します。

## 画面で操作する

一覧を表示し「この行を編集」を押します。課題名を変更して「変更を保存」を押します。空欄・100文字超では入力検証が表示されます。DB未設定なら日本語の案内が表示されます。

## ソースのしくみ

LearningEditInput はEntityとは別の入力用クラスです。Read時のxminをVersionとして保持し、SaveAsyncでサーバー側の1〜100文字検証と現在版の照合を行います。DbContextは各操作でFactoryから生成・破棄します。

## 実務での注意点

画面にある古い値を、そのまま別ユーザーの更新へ上書きしてはいけません。版が異なれば保存を拒否します。 この教材にAD本人認証と業務認可はまだ実装していません。Step61〜70で学ぶまでは架空の開発用DBだけを操作してください。

## 確認問題と答え

**Q. 入力DTOを使う理由は？** 追跡中DbContextとDB Entityを長時間UIに置かず、入力可能な列だけを明確にするためです。

## 自分で試す演習

成功操作と否定操作（空欄、DB未設定、競合、取消、行削除のうち該当するもの）をそれぞれ実行して、画面の日本語案内が異なることを確かめましょう。
