# 学習順008：RazorでC#の値を表示する

## 到達目標と前提

これまでのHTMLには固定の日本語文を直接書きました。RazorではC#の値をHTMLの一部として表示できます。ただし、画面に何が表示されるかと、そのC#値がどこに保持されるかを区別する必要があります。ここでは架空の文字列、整数、日付、および山括弧を含む文字列を表示します。DBからデータを取得する例ではありません。WinFormsのLabel.Textへ代入する経験と比べて、値の表示方法とHTMLエンコードを理解します。

この章の対象は .NET 10、Visual Studio 2026、Blazor Web App（Interactive Server）です。第1段階のHTTPとブラウザーの役割を学習済みであることを前提とします。教材画面の操作にはActive Directory・PostgreSQL・業務データを必要としません。実際の画面は **`/learn/03`** です。前のテーマから順に進んでも、この章だけを開いて確認できるよう、コードと操作方法を以下に示します。

## 1. WinForms＋Dapperとの対応を確認する

| 観点 | WinForms＋Dapper経験者の見方 | 本教材のBlazor | 
| --- | --- | --- |
| 値の表示 | label.Textへの代入 | HTML内の@displayName等の式 |
| データの定義 | Formのフィールド | Razorの@code内のC#フィールド |
| 日付書式 | DateTime.ToString | 同じC#のToStringとja-JP |
| HTMLとの関係 | ラベルはテキスト | HTML出力時に通常の文字列をエンコード |
| 値の変更 | イベントでTextを更新する例が多い | 再描画時に式の結果を反映 |
| 実データ | Dapper等でDB読込 | ここでは固定値のみ |

比較する際は、WinFormsで自分が操作するPCと、業務アプリのサーバー側に配置されるC#が同じ場所とは限らない点を意識してください。ここに示すDapperは経験上の比較対象です。今回のサンプルはDapperやEF Coreを実行しません。後続のDB編では、業務データを取得する際に認可を行った上でサーバー側からアクセスします。

## 2. 実際のRazor画面コードを読む

次は実装中の主要部分の抜粋です。コンポーネント全体の他のHTMLや見出しは省略していますが、掲載した要素・表示文字列と識別子は現行実装に対応します。

```razor
<dl class="value-list">
    <div><dt>表示名</dt><dd>@displayName</dd></div>
    <div><dt>表示するステップ数</dt><dd>@stepCount</dd></div>
    <div><dt>例の日付</dt><dd>@sampleDate.ToString("yyyy年M月d日", CultureInfo.GetCultureInfo("ja-JP"))</dd></div>
</dl>
<p class="example-output">@sampleText</p>
```

`RazorSyntaxPage.razor`の`@code`に上記の固定値があります。画面の`@displayName`は文字列の値、`@stepCount`は整数3を表示します。日付は`CultureInfo.GetCultureInfo("ja-JP")`と`yyyy年M月d日`の書式を使い、2026年10月26日と表示します。`sampleText`には山括弧を含む文字列が入っていますが、普通の文字列として`@sampleText`を置くとHTMLタグとして実行されません。画面に見える文字列とDOMの要素構造をElementsで確認してください。これは出力時のHTMLエンコードを理解する学習用実装です。

## 3. C#または関連する実コードを確かめる

次も現行実装から抜き出した部分です。画面や状態の理解に必要な部分を残しています。先のコードと照らして、HTMLが担当する表示とサーバー側の処理を切り分けてください。

```csharp
// Step03の値は架空の固定データです。DB・ADへの接続は行いません。
private readonly string displayName = "学習者";
private readonly int stepCount = 3;
private readonly DateTime sampleDate = new(2026, 10, 26);

// HTMLと混同されないよう、通常の文字列として表示します。
private readonly string sampleText = "<重要>これは文字列です</重要>";
```

RazorはHTMLを書きながらC#の式を挿入できる記法です。`@`のあとに変数や式を置くため、同じC#のデータ型・書式設定の知識を利用できます。一方、表示される場所はWinFormsのラベルではなくブラウザーのHTMLです。とくに利用者由来の文字列を扱うときは、単に文字列が表示できることと、HTMLとして解釈してよいことを混同しないでください。このステップは意図的に`sampleText`へタグのような値を置き、安全な通常出力を観察します。実際の業務アプリではエンコードだけで認可が完了するわけではなく、閲覧者の部署・役割・失効も別に確認する必要があります。また、`readonly`なフィールドはここでは初期値を固定するために使っていますが、DBに保存された永続データを表しているわけではありません。

## 4. ブラウザー・サーバー・状態の境界

今回扱う値や表示は、画面が提供する学習用の例です。Interactive ServerのC#はサーバー上で動き、ブラウザーがHTMLを描画します。初期のHTTP応答で文字が見えることと、対話型イベントに対応するC#が実行できることは同じ確認ではありません。ブラウザーのNetwork、Consoleと、Webサーバーの実行ログやVisual Studioのブレークポイントは、それぞれ調べられる範囲が異なります。

また、画面を開けたことをDB保存の完了や業務権限の成立と取り違えないでください。実業務では利用者のAD本人認証に加え、既存DB台帳を正本とした権限判定、必要な操作記録が別に必要です。ここで扱うサンプルには、それらの業務処理を追加したとは主張しません。

## 5. 順番に操作して確かめる

1. `/learn/03`を開き、表示名が学習者、ステップ数が3であることを確認する。
2. 例の日付が2026年10月26日と日本語で表示されていることを読む。
3. 山括弧を含む`<重要>これは文字列です</重要>`がそのまま文字として見えることを確認する。
4. 開発者ツールのElementsでこのテキストが新たな`重要`要素になっていないことを確認する。
5. `displayName`を実在しない学習用の名前へ変更して画面の再表示を試す。
6. 変更を元に戻し、次の学習順009の比較画面を開く。

画面の文言を変更する演習では、保存後に表示が更新されたことだけを確認するのではなく、**どのRazor/C#の行を変えたことで、どのHTMLや表示状態が変わったか**を説明してください。学習用データには架空の値を使用し、実在する利用者の名前・認証情報は入力しません。

## 6. 症状別の切り分け表

| 症状 | 確認箇所 | 判断と対応 |
| --- | --- | --- |
| 文字列が出ない | @code内の名前と画面式 | 大文字・小文字やスコープを照合 |
| 日付表示が想定と違う | ToStringの書式・ja-JP指定 | 固定値と表示形式を分けて確認 |
| 山括弧がタグになった | HTMLとして解釈する記法を追加していないか | 通常の文字列表示でエンコードされるか確認 |
| C#のビルドエラー | 引用符・セミコロン・型 | Razorの表示式と@codeの境界を調べる |
| 値を変えても反映されない | 変更したファイルと起動状態 | 保存・再ビルド・再読込を確認 |

診断の順序は、まずサーバーへ接続できるか、次にURLとHTMLが一致するか、その後に対話型接続とC#イベントが働くか、最後に表示・値の仕様が正しいかという順番です。ChromeのConsoleに表示がないからといって、サーバー側のC#が正常だったとは判断できません。逆に、意図的に無効化したボタンの動作を通信障害と決め付けることも避けます。

## 7. 演習問題と詳しい解答

### 問題1

`sampleDate`は現在の日付になりますか。

**解答と根拠：** いいえ。`new DateTime(2026, 10, 26)`という固定値なので、実行した日の現在時刻は読み取りません。

### 問題2

なぜ山括弧が画面に文字として見えるのですか。

**解答と根拠：** Razorの通常の文字列出力がHTMLエンコードを行うためです。HTMLタグとして扱わせる目的でない文字列をそのままHTMLへ注入しない設計を確認してください。

### 問題3

`@displayName`の値を別ユーザーのDB値に変えるだけで認可は済みますか。

**解答と根拠：** 済みません。画面での表示方法と業務データを読む権限判定は別です。後の段階で既存台帳を正本として操作ごとに認可します。
