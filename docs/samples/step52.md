# ステップ52：Dialogと編集フォーム

## できるようになること

MudBlazorのIDialogServiceを使って入力・保存・取消・結果通知を分離する。 Visual Studio 2026、.NET 10、Blazor Interactive Server、MudBlazor 9、EF Core 10、開発用PostgreSQL 18を使用します。

## 前提条件

Step31〜50のDbContextFactory、CRUD、ServerData、楽観的排他を学んだ後に進みます。DB未設定の場合は実操作できず、日本語の設定案内を表示します。

## 画面で操作する

ステップ52で架空課題の「ダイアログで編集」を押します。値を入力し「取消」を押すと未保存で閉じます。再度開き「保存して閉じる」で保存成功なら一覧が更新されます。

## ソースのしくみ

EditDialogはModelのCopyを編集し、EditFormのDataAnnotationsValidatorとSaveAsyncによる再検証を行います。二重送信防止の_savingを使用し、成功したときだけDialog.Closeします。

## 実務での注意点

Dialogの表示・非表示は業務認可ではありません。キャンセルで更新メソッドを呼ばない点、競合したらダイアログを閉じない点が重要です。 この教材にAD本人認証と業務認可はまだ実装していません。Step61〜70で学ぶまでは架空の開発用DBだけを操作してください。

## 確認問題と答え

**Q. ダイアログの保存が失敗したら？** 閉じずに日本語のエラーを表示し、DB側の確認・再読み込みを促します。

## 自分で試す演習

成功操作と否定操作（空欄、DB未設定、競合、取消、行削除のうち該当するもの）をそれぞれ実行して、画面の日本語案内が異なることを確かめましょう。
