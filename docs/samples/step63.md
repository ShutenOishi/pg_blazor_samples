# ステップ63：SIDとDB利用者の対応

## できるようになること

ADの認証とアプリ台帳の登録を分離する。Visual Studio 2026、.NET 10、Blazor Interactive Server、PostgreSQL 18、EF Core 10を前提にします。

## 画面で確認する

1. ステップ63を開き「現在の認証・DB照合状態を確認」を実行する。
2. Windows認証を使わない開発環境では匿名として**拒否**されることを確認する。
3. 取得した状態と、認証・業務認可の違いを説明する。

## ソースコードのポイント

app_user.sidを完全一致で照合します。本人認証が成功してもDBに利用者がなければ使用できません。

- WindowsUserAccessService.ReadCurrentAsyncはAuthenticationStateProviderから**サーバーが認証した**ClaimsPrincipalを取得します。
- SIDは表示用に末尾4文字へマスクし、利用者の認証情報をログへ出しません。
- DB照合はDbContextFactoryから操作ごとに作る短命DbContextで行い、未登録・無効・権限不足は許可しません。
- DB接続不良・定義不整合はフェイルクローズします。UIから渡されたSIDは使用しません。

## 実務上の境界

開発用DBに架空利用者を登録する場合もパスワードは保存しません。

DBのapp_user / app_role / app_permission / app_user_role / app_role_permissionは認可構造の教材です。利用者登録をこの画面からは行いません。

**注意：Step61〜65は認証とDB照合の骨格です。既存の一覧・更新・CSVへのサービス側認可はStep66〜70で適用します。実データへ接続しないでください。**

## 確認問題と答え

**Q. 認証された利用者名だけで権限を判断してよい？**

**A. いいえ。** 信頼できるSIDでDB登録・有効性・権限を判定し、DB障害や未登録は拒否します。

## 自分で試す演習

1. 匿名の拒否結果を確認する。
2. SIDが使えないときに名前へフォールバックしてはいけない理由を説明する。
3. 有効な利用者でも閲覧権限がない場合の結果を確認する。
