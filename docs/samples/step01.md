# 学習順006：最初のBlazor画面を表示する

## 到達目標と前提

最初の画面にはC#の業務ロジックもデータアクセスもありません。それでもURL、ブラウザーのタイトル、画面見出し、共通ルーティングというWebアプリの基本要素が既に働いています。WinFormsのFormをデザイナーで配置する経験から始める場合、Razorファイルが「画面の定義」と「URLに結び付く部品」を兼ねていることを押さえると理解しやすくなります。ここでの目標は、表示される日本語の位置を実装と照合し、表示したい文字列を変更して再起動するまでを自分で説明できることです。

この章の対象は .NET 10、Visual Studio 2026、Blazor Web App（Interactive Server）です。第1段階のHTTPとブラウザーの役割を学習済みであることを前提とします。教材画面の操作にはActive Directory・PostgreSQL・業務データを必要としません。実際の画面は **`/learn/01`** です。前のテーマから順に進んでも、この章だけを開いて確認できるよう、コードと操作方法を以下に示します。

## 1. WinForms＋Dapperとの対応を確認する

| 観点 | WinForms＋Dapper経験者の見方 | 本教材のBlazor | 
| --- | --- | --- |
| 画面の構成単位 | Formクラスとデザイナー | RazorコンポーネントとHTML |
| 起動時の入口 | Application.Runなど | ASP.NET CoreのWebホスト |
| アドレス | 通常はフォーム名など | @pageで指定するURL |
| 見出し | LabelなどのText | HTMLのh1 |
| ウィンドウタイトル | Form.Text | PageTitle |
| DB接続 | フォームイベントからDapperを呼ぶ場合がある | この例ではDBを一切呼ばない |

比較する際は、WinFormsで自分が操作するPCと、業務アプリのサーバー側に配置されるC#が同じ場所とは限らない点を意識してください。ここに示すDapperは経験上の比較対象です。今回のサンプルはDapperやEF Coreを実行しません。後続のDB編では、業務データを取得する際に認可を行った上でサーバー側からアクセスします。

## 2. 実際のRazor画面コードを読む

次は実装中の主要部分の抜粋です。コンポーネント全体の他のHTMLや見出しは省略していますが、掲載した要素・表示文字列と識別子は現行実装に対応します。

```razor
@page "/learn/01"

<PageTitle>ステップ01：最初の画面｜Blazor ステップアップ学習</PageTitle>

<p class="eyebrow">ステップ01 / Razorの基礎</p>
<h1>はじめてのBlazor画面</h1>

<p>この文章は、Razorコンポーネントから表示しています。</p>
```

`FirstPage.razor`の`@page`が`/learn/01`を割り当てます。`PageTitle`はブラウザーのタブに使われ、`h1`は画面内の文書見出しです。両者を同じ用途のラベルと考えないでください。`section`と`h2`は本文の区切り、`a href`は普通のHTMLリンクです。特別な画面遷移コードを書かなくても、共通のルーターが行き先のコンポーネントを見つけます。`@@page`と書かれた箇所は、画面に文字列「@page」を表示するためにRazorの記号をエスケープしています。実際のURL定義は先頭の`@page`です。

## 3. C#または関連する実コードを確かめる

次も現行実装から抜き出した部分です。画面や状態の理解に必要な部分を残しています。先のコードと照らして、HTMLが担当する表示とサーバー側の処理を切り分けてください。

```razor
<section class="lesson-details">
    <h2>学ぶこと</h2>
    <p>このファイルには、画面のURLを決める <code>@@page</code> ディレクティブと、画面に表示するHTMLがあります。</p>
    <p>まだC#の処理やデータベース接続は使いません。</p>
</section>

<div class="page-navigation">
    <a href="/">学習の目次へ戻る</a>
    <a href="/learn/02">次へ：ステップ02</a>
</div>
```

最初のステップだからこそ、実行前にどこまで準備が済んでいるかを区別します。.NET 10 SDKとVisual Studio 2026は開発環境です。WebプロジェクトはHTTP要求を受けてHTMLを返す側で、ブラウザーはそのHTMLを解釈して表示します。開発PCでは両方を同じPC上で動かせますが、本番ではサーバー側のC#と利用者側の表示が分かれます。Razorに`<p>`を書いてもWinFormsのラベルオブジェクトが生成されるわけではなく、HTMLの段落がブラウザーに提示されます。ここではまだコンポーネント変数や対話型イベントを使いません。次の学習順でURLとルーティングを詳しく扱う前に、まず何も入力しない静的な画面を観察します。

## 4. ブラウザー・サーバー・状態の境界

今回扱う値や表示は、画面が提供する学習用の例です。Interactive ServerのC#はサーバー上で動き、ブラウザーがHTMLを描画します。初期のHTTP応答で文字が見えることと、対話型イベントに対応するC#が実行できることは同じ確認ではありません。ブラウザーのNetwork、Consoleと、Webサーバーの実行ログやVisual Studioのブレークポイントは、それぞれ調べられる範囲が異なります。

また、画面を開けたことをDB保存の完了や業務権限の成立と取り違えないでください。実業務では利用者のAD本人認証に加え、既存DB台帳を正本とした権限判定、必要な操作記録が別に必要です。ここで扱うサンプルには、それらの業務処理を追加したとは主張しません。

## 5. 順番に操作して確かめる

1. Visual Studio 2026で`PgBlazorSamples.slnx`を開き、Webプロジェクトを起動対象にする。
2. F5またはCtrl+F5で起動し、起動時に表示されたURLを確認する。
3. そのホストの`/learn/01`を開き、見出し「はじめてのBlazor画面」と説明文、ブラウザータブの題名を確認する。
4. `FirstPage.razor`で説明の`<p>`内の文字だけを編集し、画面に反映されることを確かめる。
5. ブラウザーの開発者ツールのElementsで`h1`と`p`を確認し、HTMLとして配置されることを観察する。
6. 元の文章に戻し、学習順007のリンクから次の画面へ進む。

画面の文言を変更する演習では、保存後に表示が更新されたことだけを確認するのではなく、**どのRazor/C#の行を変えたことで、どのHTMLや表示状態が変わったか**を説明してください。学習用データには架空の値を使用し、実在する利用者の名前・認証情報は入力しません。

## 6. 症状別の切り分け表

| 症状 | 確認箇所 | 判断と対応 |
| --- | --- | --- |
| ブラウザーが接続できない | 起動したWebサーバーのURL、ポート、起動ログ | @pageではなくサーバー起動の問題を先に確認 |
| 別の画面が出る | パスが/learn/01になっているか | URLの末尾と大文字・小文字を確認 |
| タブの題名だけ違う | PageTitleの文字列 | h1とPageTitleの役割を分けて調べる |
| 本文を直しても変わらない | 編集したファイルと起動中のプロセス | 保存・ビルドとブラウザー再読込を確認 |
| 表示が文字化けする | HTMLの文字コード指定とフォント | ブラウザー側の描画・文字コードを確認 |

診断の順序は、まずサーバーへ接続できるか、次にURLとHTMLが一致するか、その後に対話型接続とC#イベントが働くか、最後に表示・値の仕様が正しいかという順番です。ChromeのConsoleに表示がないからといって、サーバー側のC#が正常だったとは判断できません。逆に、意図的に無効化したボタンの動作を通信障害と決め付けることも避けます。

## 7. 演習問題と詳しい解答

### 問題1

`@page`を消したらどうなりますか。

**解答と根拠：** そのファイルだけを直接開くためのルートがなくなります。ほかの画面から部品として使うことは別ですが、学習用URLに直結する定義がなくなるため`/learn/01`の解決を確認する必要があります。

### 問題2

`PageTitle`と`h1`を別の日本語にしてもよいですか。

**解答と根拠：** 用途が異なるので可能です。前者は文書タイトル、後者は本文見出しです。ただし学習用画面では両方が何を示すか分かる表現にします。

### 問題3

ここでDapperの接続文字列を設定する必要がありますか。

**解答と根拠：** 不要です。画面は静的な日本語文字列を返すのみで、認証・認可もDB操作もこのステップの要件ではありません。
