# ステップ70：Windows Server 2025の実機受入を分ける

## 到達目標

Kerberos・IIS、外部台帳、監査、同時接続を実行例で理解します。Visual Studio 2026、.NET 10、MudBlazor、EF Core 10、PostgreSQL 18を用います。

## このステップで学ぶこと

CIで偽のClaimsPrincipalを使った試験が成功しても、現実のAD、IIS、Kerberosを証明したことにはなりません。運用前には必ず実機で構成・拒否・通信・監査を検証します。

## 画面の操作

1. 画面で「現在の更新権限を確認」を押し、匿名拒否を確認する。
2. Windows Server 2025 + IIS + KerberosでWindows本人を識別する。
3. FDW遅延・切断、名前変更/再使用、権限剥奪、他部署の閲覧と更新を実機で否定試験する。

## C#とSQLのしくみ

Application NameはPgBlazorSamples.Webに固定してプールを再利用します。DB接続の診断情報であり、個人の監査証跡ではありません。監査の永続化・相関ID・保存先は運用設計が別途必要です。明示ログイン業務はADパスワードの入力画面を作らず、Windows認証専用HTTP経路と短命Cookieの安全設計を採用します。

## 安全性と境界

業務用の利用者登録機能は作りません。認可の正本は管理者が構成する既存テーブル/外部テーブルを表す読み取り専用ビューです。匿名・権限なし・DB障害では拒否し、データやSQL結果を出しません。

実AD/IIS/Kerberosの認証成功はCIでは代替できません。業務で使う場合は実環境の接続方式・本人・権限更新・監査を別途受け入れてください。

## 確認問題と解答

**Q. CIが成功すれば実業務公開してよい？** いいえ。実機受入と監査・容量試験を完了する必要があります。
