# 学習順013：親から子へ値を渡す

**実装ソース：** [対応するRazor実装](../../src/PgBlazorSamples.Web/Components/Samples/Step07/ParametersPage.razor)。画面の正規URLは `/learn/013` です。

## 到達目標と画面の前提
この学習では、Razorコンポーネントを親画面と子部品に分ける理由を、実際の日本語カード表示を使って理解します。画面のURLは`/learn/013`、親は`ParametersPage.razor`、子は`GreetingCard.razor`です。学習順011の双方向バインディングと012の繰り返し・条件表示を理解していれば始められます。Visual Studio 2026、.NET 10とChromeを使い、AD・DB・Dapper・MudBlazorはこの実習には不要です。

WinFormsではUserControlをフォームに配置し、フォームからプロパティを設定する場合があります。Blazorでは子コンポーネントをHTMLタグに似た書き方で配置し、`[Parameter]`で公開した値を親が指定できます。ただしRazorのパラメーターは親が所有する入力です。子が受け取った値を勝手に書き換えると、親の次の描画で意図しない状態になります。この境界を守れることを目標にします。学習者は実装の2ファイルを開き、どの値が誰の所有物か説明してください。

## WinFormsとの比較
| 観点 | WinFormsのUserControl | 今回のRazorコンポーネント |
| --- | --- | --- |
| 部品の再利用 | デザイナーやC#で配置 | `<GreetingCard ... />`を複数配置 |
| 入力の受け取り | 公開プロパティへ代入することが多い | `[Parameter]`付きプロパティ |
| 値の所有者 | FormまたはUserControlの設計に依存 | 今回は親が`learnerName`を保持 |
| 値の変更通知 | イベントを登録 | 次の学習で`EventCallback<T>`を使う |
| UI再描画 | TextやControlを手動で更新する例が多い | 親の状態変更に応じて子に値が届く |
| DBの扱い | フォームからDapperを呼ぶことがある | この2つの部品にはDB操作がない |

## 実コード1：親の入力欄と2枚のカード
```razor
@page "/learn/013"
@using PgBlazorSamples.Web.Components.Samples.Step07
<label class="field-label" for="step07-name">練習用の表示名</label>
<input id="step07-name" type="text" class="text-input" maxlength="20"
       @bind="learnerName" @bind:event="oninput" autocomplete="off" />
<GreetingCard LearnerName="@learnerName" Topic="親が入力した名前" />
<GreetingCard LearnerName="架空の利用者" Topic="別の値でも同じ部品" />
```

上の例は現行親画面の主要部分です。`@using`は子部品の名前空間を参照します。`@bind`により親の`learnerName`が更新されると、1枚目の`LearnerName`に新しい値が渡ります。2枚目には固定文字列「架空の利用者」を渡しているため、上の入力を変えても変化しません。1つのRazor部品をコピーせず2回使っていることを画面で確認してください。`Topic`も別々の文字列を渡しており、同じ部品で表示内容を変更できる設計です。

## 実コード2：子部品の受け口
```razor
<article class="lesson-details" data-testid="greeting-card">
    <h3>@Topic</h3>
    <p>こんにちは、<strong>@LearnerName</strong> さん。</p>
    <p class="hint">同じ部品を、異なる値で再利用しています。</p>
</article>

@code {
    // Parameterは親が渡す入力です。子コンポーネント内で書き換えません。
    [Parameter]
    public string LearnerName { get; set; } = "ゲスト";

    [Parameter]
    public string Topic { get; set; } = "学習";
}
```

`[Parameter]`は親から設定できる公開プロパティを示します。既定値「ゲスト」と「学習」は親から値が渡らない場合の初期値です。今回の親は両方を指定しているので、通常はこの既定表示を見ません。`@LearnerName`は文字列として安全に表示され、HTMLタグの実行を意図するものではありません。業務用の名前や権限をそのまま共通部品へ渡す場合でも、表示前に必ずサーバー側の認可を終える必要があります。部品に渡せたことは閲覧を許されたことの証明にはなりません。

## 実コード3：親の状態
```csharp
// バインドしている値は親画面が所有します。
private string learnerName = "練習太郎";
```

入力欄の初期表示も1枚目のカードも「練習太郎」です。この変数を子にコピーして保持するのではなく、親が現在の値を渡します。親が変わらない限り2枚目の固定カードも変わりません。WinFormsの複数フォームで同じ文字列を重複管理すると変更漏れが発生しやすいように、Webでも複数コンポーネントが同じ状態を勝手に所有すると整合性を失います。

## 手順：親の値がどの子へ届くか
1. `/learn/013`を開き、2枚のカードが描画されていることを確かめます。
2. 1枚目の「親が入力した名前」には「練習太郎」、2枚目の「別の値でも同じ部品」には「架空の利用者」が表示されます。
3. 「練習用の表示名」に「練習花子」を入力すると1枚目だけが更新されます。
4. 入力欄を空にすると1枚目は名前のない挨拶になります。`GreetingCard`自体が消えるわけではありません。
5. 入力欄にHTMLタグ風の文字列を入力し、子部品内で通常の文字として表示されることを確認します。
6. `GreetingCard`の参照先を確認し、2枚のカードが同じ`GreetingCard.razor`で描画されていることを確かめます。
7. 再読込して初期値の「練習太郎」に戻ることを確認します。子部品はDB保存をしていません。

## 失敗したときの切り分け
| 症状 | 調べる対象 | 修正の考え方 |
| --- | --- | --- |
| 子のカードが出ない | `@using`とコンポーネント名 | 名前空間と部品の参照を一致させる |
| 1枚目だけ更新されない | `@bind`と`LearnerName="@learnerName"` | 親が新しい値を渡しているかを確認 |
| 2枚目も変わる | 2枚目の固定引数 | 両方に親の変数を渡していないか |
| 子の値が勝手に戻る | `[Parameter]`の子側代入 | 子で親の入力値を書き換えない |
| 20文字以上入らない | `maxlength="20"` | この画面の入力上限による正常動作 |
| DBに入力内容がない | DB操作の有無 | 永続化がないのは設計どおり |

## 演習と詳しい解答
**演習1：** 2枚目も入力に連動させるには、親のどこを変更しますか。

**解答1：** 2枚目の`LearnerName="架空の利用者"`を`LearnerName="@learnerName"`に変更します。子`GreetingCard`の中身は変更不要です。これが部品再利用の効果です。修正した状態で入力を変え、2枚とも同じ値になることを確認できます。

**演習2：** 子の`LearnerName`をクリック操作で直接別文字列に変更してもよいでしょうか。

**解答2：** 親から渡す値の所有責任が崩れるため避けます。親は次の再描画で元の値を渡し直す可能性があります。変更したいときは、次の学習順014で扱うイベント通知を子から親へ送り、親が自身の`learnerName`を更新します。

**演習3：** `[Parameter]`の初期値「ゲスト」が表示される条件は何ですか。

**解答3：** 親が`LearnerName`を指定しない場合などです。ただし今回の親画面は両方のカードへ値を渡しているので、通常の実習で「ゲスト」は表示されません。コードの既定値と実画面の値を混同しないことが大切です。

**演習4：** Dapperで取得した業務データを子の一覧カードへ渡すとき、子の非表示設定だけで部署外の情報を保護できますか。

**解答4：** できません。サーバー側で本人を特定して既存DB台帳から操作権限を確認し、権限内の結果のみ取得してから表示部品へ渡します。今回の画面にはDB問い合わせ・部署認可は実装されていません。

**演習5：** 同じ部品を10枚並べる場合、10個のRazorファイルが必要ですか。

**解答5：** 必要ありません。親から同じ`GreetingCard`を繰り返し使えます。一覧なら`@foreach`を使う選択もできます。ただし項目ごとの状態、安定したキー、表示負荷は必要に応じて考慮します。
