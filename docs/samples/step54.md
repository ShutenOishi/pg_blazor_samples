# ステップ54：xmin競合と差分の確認

## できるようになること

2ウィンドウで同じ行を編集し、古い版の保存を拒否する。 Visual Studio 2026、.NET 10、Blazor Interactive Server、MudBlazor 9、EF Core 10、開発用PostgreSQL 18を使用します。

## 前提条件

Step31〜50のDbContextFactory、CRUD、ServerData、楽観的排他を学んだ後に進みます。DB未設定の場合は実操作できず、日本語の設定案内を表示します。

## 画面で操作する

同じ行を2つのウィンドウで開きます。一方を保存した後に古い画面から別の値を保存すると競合の日本語メッセージと最新タイトルが出ます。「最新状態に読み替える」で再編集します。

## ソースのしくみ

SaveAsyncは読み取ったVersionと更新時のxminを比較し、保存直前のDbUpdateConcurrencyExceptionも捕捉します。削除済みはMissingで別扱いです。

## 実務での注意点

競合を勝手に再試行すると他者の変更を失う可能性があります。比較・再読込・手動の再編集を原則にします。 この教材にAD本人認証と業務認可はまだ実装していません。Step61〜70で学ぶまでは架空の開発用DBだけを操作してください。

## 確認問題と答え

**Q. xminはC#から手動で増やす？** いいえ。PostgreSQLが行更新で変更し、EF Coreが読み取って照合します。

## 自分で試す演習

成功操作と否定操作（空欄、DB未設定、競合、取消、行削除のうち該当するもの）をそれぞれ実行して、画面の日本語案内が異なることを確かめましょう。
