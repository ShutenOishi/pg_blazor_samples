# 学習順010：ボタンのイベントを扱う

**実装ソース：** [対応するRazor実装](../../src/PgBlazorSamples.Web/Components/Lessons/Stage02/L010L010EventPage.razor)。画面の正規URLは `/learn/010` です。

## 到達目標と前提

学習順009で対話型C#イベントがどこで動くかを調べました。今度はボタンを3種類に増やし、増やす・減らす・初期値に戻すという操作を試します。WinFormsならボタンのClickイベントからC#メソッドを呼び出し、Label.Textを更新することがあります。BlazorではHTMLに`@onclick`を記述し、変更後の`count`をRazorが再描画します。特に重要なのは、表示上の無効化と処理側の条件を両方持つことです。

この章の対象は .NET 10、Visual Studio 2026、Blazor Web App（Interactive Server）です。第1段階のHTTPとブラウザーの役割を学習済みであることを前提とします。教材画面の操作にはActive Directory・PostgreSQL・業務データを必要としません。実際の画面は **`/learn/010`** です。前のテーマから順に進んでも、この章だけを開いて確認できるよう、コードと操作方法を以下に示します。

## 1. WinForms＋Dapperとの対応を確認する

| 観点 | WinForms＋Dapper経験者の見方 | 本教材のBlazor | 
| --- | --- | --- |
| イベントへの接続 | Button.Clickハンドラー | buttonの@onclickにメソッドを渡す |
| 値の保持 | Form内のフィールド | Razorコンポーネント内のcount |
| 表示更新 | Label.Textを明示的に変更 | @count式の再描画 |
| 操作の無効化 | Enabled=false | disabled属性 |
| 負数の防止 | イベント内のif等 | Decrement()内のif |
| 状態の保存 | 別途Dapper/ファイル等へ保存 | この画面では永続化しない |

比較する際は、WinFormsで自分が操作するPCと、業務アプリのサーバー側に配置されるC#が同じ場所とは限らない点を意識してください。ここに示すDapperは経験上の比較対象です。今回のサンプルはDapperやEF Coreを実行しません。後続のDB編では、業務データを取得する際に認可を行った上でサーバー側からアクセスします。

## 2. 実際のRazor画面コードを読む

次は実装中の主要部分の抜粋です。コンポーネント全体の他のHTMLや見出しは省略していますが、掲載した要素・表示文字列と識別子は現行実装に対応します。

```razor
<p class="counter-display" role="status" aria-live="polite">
    現在の数値：<strong data-testid="counter-value">@count</strong>
</p>
<div class="practice-actions">
    <button type="button" @onclick="Increment">1増やす</button>
    <button type="button" @onclick="Decrement" disabled="@(count == 0)">1減らす</button>
    <button type="button" class="secondary-button" @onclick="Reset">0に戻す</button>
</div>
```

`L010EventPage.razor`には`count`、`Increment()`、`Decrement()`、`Reset()`が実装されています。値の初期値はC#の`int`の既定値0です。`disabled="@(count == 0)"`は0のとき減らすボタンを押せなくします。ただし画面上の無効化だけを業務上の制約として信頼してはいけません。実メソッド`Decrement()`の中でも`if (count > 0)`を確認しており、値を0未満へ減らしません。`role="status"`と`aria-live="polite"`は値の変化を支援技術へ伝えるための指定です。

## 3. C#または関連する実コードを確かめる

次も現行実装から抜き出した部分です。画面や状態の理解に必要な部分を残しています。先のコードと照らして、HTMLが担当する表示とサーバー側の処理を切り分けてください。

```csharp
// この画面に表示するカウンターです。利用者固有の状態を共有サービスには保持しません。
private int count;

// ボタン操作に対応するイベント処理です。
private void Increment() => count++;

// 0より小さな値にならないよう、表示条件に加えて処理側でも防ぎます。
private void Decrement()
{
    if (count > 0)
    {
        count--;
    }
}

// 演習を何度でも試せるよう、初期値に戻します。
private void Reset() => count = 0;
```

WinFormsでClickイベントの中に`label.Text = ...`を書く場合と異なり、このRazorコンポーネントでは`count`の値を変更した後の再描画に任せています。`@onclick="Increment"`はイベントを受け取ったときに実行するメソッドを指定します。`@onclick="Increment()"`のように式を即時呼び出しとして書くのとは使い方が違います。HTMLの`button`に`type="button"`を付けているのは、あとでフォーム内へ移したとき意図しない送信を避けるためです。カウンターの現在値は単一の画面状態であり、利用者全員の共有変数でもPostgreSQLのレコードでもありません。ブラウザーを再読み込みして新しいコンポーネントになると初期値に戻ります。DBへの更新が必要な業務画面では、後のステップで入力検証、サーバー側認可、競合制御、監査などを組み合わせます。

## 4. ブラウザー・サーバー・状態の境界

今回扱う値や表示は、画面が提供する学習用の例です。Interactive ServerのC#はサーバー上で動き、ブラウザーがHTMLを描画します。初期のHTTP応答で文字が見えることと、対話型イベントに対応するC#が実行できることは同じ確認ではありません。ブラウザーのNetwork、Consoleと、Webサーバーの実行ログやVisual Studioのブレークポイントは、それぞれ調べられる範囲が異なります。

また、画面を開けたことをDB保存の完了や業務権限の成立と取り違えないでください。実業務では利用者のAD本人認証に加え、既存DB台帳を正本とした権限判定、必要な操作記録が別に必要です。ここで扱うサンプルには、それらの業務処理を追加したとは主張しません。

## 5. 順番に操作して確かめる

1. `/learn/010`を開き「現在の数値：0」と、減らすボタンが無効なことを確認する。
2. 「1増やす」を2回押し、2となることを確認する。
3. 「1減らす」を1回押し、1となることを確認する。
4. 「0に戻す」を押し、0になり減らすボタンが再び無効になることを確認する。
5. Visual Studioで`Decrement()`にブレークポイントを置き、処理側の`if`を確認する。
6. ページを再読み込みし、値が保存されていないことを確認した後、第2組の復習を開く。

画面の文言を変更する演習では、保存後に表示が更新されたことだけを確認するのではなく、**どのRazor/C#の行を変えたことで、どのHTMLや表示状態が変わったか**を説明してください。学習用データには架空の値を使用し、実在する利用者の名前・認証情報は入力しません。

## 6. 症状別の切り分け表

| 症状 | 確認箇所 | 判断と対応 |
| --- | --- | --- |
| 押しても数値が変わらない | 対話型接続と@onclick | 接続・イベントのどちらが不成立か切り分け |
| マイナスになってしまう | Decrement()のifと現在値 | 表示側disabledだけで防いでいないか確認 |
| 減らすが押せない | countが0になっていないか | 想定通りの拒否と通信障害を区別 |
| 再読み込みで0に戻った | コンポーネント再作成 | 永続保存を実装していないので正常 |
| フォーム内でボタン送信した | type=buttonが付いているか | クリックとHTMLフォーム送信を区別 |

診断の順序は、まずサーバーへ接続できるか、次にURLとHTMLが一致するか、その後に対話型接続とC#イベントが働くか、最後に表示・値の仕様が正しいかという順番です。ChromeのConsoleに表示がないからといって、サーバー側のC#が正常だったとは判断できません。逆に、意図的に無効化したボタンの動作を通信障害と決め付けることも避けます。

## 7. 演習問題と詳しい解答

### 問題1

なぜ`disabled`に加えて`if (count > 0)`が必要ですか。

**解答と根拠：** 利用者向け表示の制約と、処理そのものの制約を分けるためです。サーバー側処理の安全性をHTMLの無効化だけに依存させない考え方は業務画面でも重要です。

### 問題2

2回押してからリロードしたとき2が残りますか。

**解答と根拠：** この画面では残りません。C#フィールドはDBなどへ永続化されず、新しいコンポーネントでは初期値0です。

### 問題3

この画面で減算できない場合はエラーですか。

**解答と根拠：** 値が0なら仕様どおりの無効化です。値が正のときも減算できない場合は、接続状態やイベントとサーバーログを確認します。
