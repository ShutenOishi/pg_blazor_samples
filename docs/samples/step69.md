# ステップ69：保存直前の権限とxminを再確認

## 到達目標

行単位の編集許可、版競合、一括処理の原子性を実行例で理解します。Visual Studio 2026、.NET 10、MudBlazor、EF Core 10、PostgreSQL 18を用います。

## このステップで学ぶこと

閲覧権限と編集権限は別物です。部署条件で取得できる行だけを更新し、xminが変化したら上書きしないようにします。

## 画面の操作

1. 架空課題の番号を入力し、詳細を取得する。
2. 編集可能な場合にだけ課題名を変更する。
3. can_editがない場合、他部署のID、古いxmin、DB停止で更新できないことを試験で確認する。

## C#とSQLのしくみ

SaveAsyncは編集権限を判断し、対象行のUnitCodeとxminを確認します。更新直前にも台帳へ問い合わせます。一括更新では対象IDをすべて同じ部署に限定し、1件でも権限外や競合があればトランザクションを確定しません。

## 安全性と境界

業務用の利用者登録機能は作りません。認可の正本は管理者が構成する既存テーブル/外部テーブルを表す読み取り専用ビューです。匿名・権限なし・DB障害では拒否し、データやSQL結果を出しません。

実AD/IIS/Kerberosの認証成功はCIでは代替できません。業務で使う場合は実環境の接続方式・本人・権限更新・監査を別途受け入れてください。

## 確認問題と解答

**Q. 一括更新のうち1件だけ他部署だったら？** 全件を取り消します。
