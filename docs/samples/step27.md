# 学習順37：確認ダイアログで実行と中止を分ける

**実装ソース：** [対応するRazor実装](../../src/PgBlazorSamples.Web/Components/Lessons/Stage04/L037DialogPage.razor)。画面の正規URLは `/learn/037` です。

**実習URL：`/learn/037`。** 第4段階・第8組の2本目です。ここで扱う架空データ・模擬処理は業務DBに保存されません。

## できるようになること
WinFormsの`MessageBox.Show`に相当する確認画面を、MudBlazorの`IDialogService`で表示します。`MudDialogProvider`との関係、`bool?`で返る結果の意味、確認と保存・認可が別であることを学びます。

## 前提と操作
学習順031のDI登録とProvider、学習順025の`@inject`が前提です。DB・ADは不要です。`/learn/037`を開きます。

1. 初期表示は「まだ選択していません。」です。
2. 「確認ダイアログを開く」を押すと「架空の処理を実行しますか？」と表示される。
3. 「中止」を選ぶと「中止しました。」になる。
4. 再び開いて「実行する」を選ぶと「実行を選びました（保存はしていません）。」になる。

## 実装の中心部分

```razor
@page "/learn/037"
@inject IDialogService Dialogs

<MudButton OnClick="ConfirmAsync">
    確認ダイアログを開く
</MudButton>
<p role="status">@_result</p>

@code {
    private string _result = "まだ選択していません。";

    private async Task ConfirmAsync()
    {
        bool? confirmed = await Dialogs.ShowMessageBoxAsync(
            "練習用の確認",
            "架空の処理を実行しますか？",
            yesText: "実行する",
            cancelText: "中止");

        _result = confirmed == true
            ? "実行を選びました（保存はしていません）。"
            : "中止しました。";
    }
}
```

`IDialogService`は`Program.cs`の`AddMudServices()`で利用できるようになり、共通レイアウトの`MudDialogProvider`が画面上へダイアログを表示します。この例は`bool?`で結果を受け取り、**明示的な`true`の場合だけ「実行を選んだ」と扱います**。中止や閉じる操作は実行扱いにしません。

## 操作の処理順
1. ブラウザーでボタンを押す。
2. サーバーの`ConfirmAsync`が`ShowMessageBoxAsync`を呼ぶ。
3. MudBlazorがダイアログを描画し、選択結果を非同期で返す。
4. `true`なら実行選択のメッセージ、その他なら中止のメッセージを設定する。
5. Razorの`_result`表示を更新する。

ここでは確認結果を表示するだけで、ファイルやDBを書き換える処理はありません。

## 重要な区別
確認ダイアログで「実行する」が選ばれても、認証済みの本人か、DBに操作権限があるか、二重送信ではないかは分かりません。実際の更新処理では**確認後のサービス呼び出しで改めて入力・本人・業務権限・競合を検査**する必要があります。

## よくある問題
- ダイアログが開かない場合は`IDialogService`の登録と`MudDialogProvider`、描画モードを確認する。
- `confirmed != false`で実行扱いにすると、`null`の中止も実行する可能性があります。`confirmed == true`を使います。
- 確認UIがあるだけでDB更新が安全になるわけではありません。


## WinForms＋Dapperと非同期確認の違い

| 観点 | WinFormsでの典型例 | Blazorの実装 | 保存時の追加責任 |
| --- | --- | --- | --- |
| ダイアログ | MessageBox.Show | IDialogService.ShowMessageBoxAsync | 確認後の再検証 |
| 結果 | DialogResult.Yes | bool?のtrue | true以外は不実行 |
| 呼び出し | イベントハンドラー | 非同期のConfirmAsync | 例外・取消の扱い |
| 依存サービス | フォーム内で直接作成しがち | DIから注入 | 業務サービスの寿命 |
| DB | DapperのExecuteなど | この画面では操作しない | 認可・競合・監査 |

## 呼び出し元とProviderを読み解く

`@inject IDialogService Dialogs`は登録済みのダイアログサービスを現在のRazorコンポーネントに受け取る記述です。実際の画面には、別のダイアログ部品のインスタンスをnewして表示するコードはありません。`AddMudServices()`でサービスが登録され、共通レイアウトの`MudDialogProvider`がダイアログを画面へ描画します。したがって画面側は「表示して、利用者の返答を待つ」ことだけに集中できます。

次は実際のアプリ全体の組合せを読むための抜粋です。画面側の`ConfirmAsync`だけをコピーしても、アプリにサービス登録とProviderがないと同じ操作は成立しません。

```csharp
// Program.csでMudBlazorの共通サービスを登録する。
builder.Services.AddMudServices();
```

```razor
@* 共通レイアウトからProviderを配置する。 *@
<MudDialogProvider />
```

`ShowMessageBoxAsync`は`Task<bool?>`の結果をawaitします。待機中にブラウザーで表示されるのはダイアログです。メソッドの後続処理は選択が戻ってから進みます。特に`null`は「はっきりyesを選択した」証拠ではありません。`confirmed != false`と書くとnullを許すため、この教材の比較式は`confirmed == true`です。

## 操作の再現と切り分け

1. `/learn/037`を開いて初期メッセージを読む。
2. 開くボタンを一度押し、ダイアログの見出しと質問を確認する。
3. 「中止」を選択し、元の画面に「中止しました。」が出ることを確かめる。
4. 再度開いて「実行する」を押し、「保存はしていません」の注意書きを読む。
5. ブラウザーを再読込して初期メッセージに戻ることを確認し、DB履歴ができたものと誤解しない。

| 症状 | 切り分け | 対処 |
| --- | --- | --- |
| ボタンを押しても開かない | AddMudServicesとMudDialogProvider | 共通登録とレイアウトを確認 |
| キャンセルが実行扱いになる | bool?比較式 | confirmed == trueへ限定 |
| ダイアログが閉じられない | 別のダイアログが残っていないか | 現在のモーダル状態を確認 |
| 「実行」でDB更新されない | 画面にDB処理があるか | この教材は結果表示だけと確認 |
| 保存許可を確認で代用した | サーバー側の認可位置 | 更新直前の本人・業務権限・競合を検査 |

## 演習を実務につなげる

**演習2：** 画面の確認でyesを選んだ直後に権限が失効した場合、更新は続行できますか。

**詳しい解答：** 続行できません。ダイアログは利用者が意図を選択しただけで、サーバーの正本台帳に基づく権限は保証しません。更新を受けるサービスが事前に整備されたDBまたは外部台帳を都度参照し、本人と対象の権限を改めて判定します。拒否時は更新せず、監査が必要な操作では監査保証が成立しなければ拒否します。確認文言や画面の表示だけで実行可否を決めないのが実業務の境界です。

**演習3：** `true`、`false`、`null`の各結果をテストする観点を説明してください。

**詳しい解答：** trueで実行選択の状態文言、falseとnullで中止の状態文言になることをそれぞれ確認します。明示的なfalseがUI構成によって返らない場合でも、nullの扱いを削らないことが重要です。保存を伴わない教材なので、行数やDBの変更を成功基準にしてはいけません。

## 演習と解答
**問：** ダイアログを閉じる操作を「実行する」とみなしてもよいですか。

**答え：** いけません。このコードは`confirmed == true`の場合だけ実行選択とし、それ以外を中止とします。
