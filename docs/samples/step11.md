# ステップ11：DI（依存性注入）とは何か

## できるようになること
部品を `new` で直接生成する方法と、DIで受け取る方法の違いを説明できます。まず「時計」の例で学びます。

## 前提
ステップ01〜10。データベースやドメイン環境は不要です。

## 完成するもの
`/learn/11` で「直接作成した時計」と「DIで受け取る時計」の挨拶を表示します。「時刻を読み直す」で更新できます。

## 実装を読む
画面内で部品を作る場合：
```csharp
directMessage = new GreetingService(new SystemClock()).GetMessage();
```

画面の先頭でDIから受け取る場合：
```razor
@inject GreetingService Greeting
```

```csharp
injectedMessage = Greeting.GetMessage();
```

DIコンテナーへの登録は `Program.cs` に書きます。利用側は、部品を作るための事情を知らずに済みます。

## よくある誤解
DIを使うと自動的にテストが完成するわけではありません。テストしやすい構造の入口です。今回の時計は実際のサーバー時刻を参照するので、時間帯によって挨拶が変わります。

## 演習
- 「時刻を読み直す」を押し、2つの結果を比較する。
- `GreetingService` が `SystemClock` を直接 `new` しないことを説明する。
