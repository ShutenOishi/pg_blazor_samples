# ステップ66：サービス側で認可を強制する

## 到達目標

業務操作の入口と旧学習サービスの境界を実行例で理解します。Visual Studio 2026、.NET 10、MudBlazor、EF Core 10、PostgreSQL 18を用います。

## このステップで学ぶこと

Windows認証済みの利用者を、既存台帳ビューで操作のたびに再判定します。認証状態やUIに権限をキャッシュしても、それを根拠に保存してはいけません。

## 画面の操作

1. 画面で「業務サービスに認可を問い合わせる」を押す。
2. 匿名のCI画面では拒否されること、業務行が出力されないことを確認する。
3. WindowsAuthentication:Enabled が true の場合、旧学習用DB操作の Configured が false になることを確認する。

## C#とSQLのしくみ

認可が必要なメソッドを SecuredLearningService に集め、WindowsUserAccessService を呼び出します。スキーム認証の成否と、DBの本人レコード・is_active・can_read・can_editを混ぜません。

## 安全性と境界

業務用の利用者登録機能は作りません。認可の正本は管理者が構成する既存テーブル/外部テーブルを表す読み取り専用ビューです。匿名・権限なし・DB障害では拒否し、データやSQL結果を出しません。

実AD/IIS/Kerberosの認証成功はCIでは代替できません。業務で使う場合は実環境の接続方式・本人・権限更新・監査を別途受け入れてください。

## 確認問題と解答

**Q. 閲覧ボタンを隠せば更新も守れる？** いいえ。直接実行されるサービスのメソッドで拒否する必要があります。
