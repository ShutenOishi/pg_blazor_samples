# ステップ55：詳細DTOと関連データ

## できるようになること

一覧の必要列と、選択時に取得する1行の詳細を分けてN+1を避ける。 Visual Studio 2026、.NET 10、Blazor Interactive Server、MudBlazor 9、EF Core 10、開発用PostgreSQL 18を使用します。

## 前提条件

Step31〜50のDbContextFactory、CRUD、ServerData、楽観的排他を学んだ後に進みます。DB未設定の場合は実操作できず、日本語の設定案内を表示します。

## 画面で操作する

一覧で「詳細を見る」を押すと、分類、期限、開始時刻、完了と版番号が表示されます。DB未設定時は案内を確認します。

## ソースのしくみ

GetDetailAsyncはAsNoTrackingとSelectで分類名をDTOへ射影し、SingleOrDefaultAsyncで必要な行のみ取得します。行ごとの追加DBアクセスを発生させません。

## 実務での注意点

1対多の子要素が大量にある場合は子一覧もServerData等で別ページングを検討します。詳細表示の権限もDB側で再検証する必要があります。 この教材にAD本人認証と業務認可はまだ実装していません。Step61〜70で学ぶまでは架空の開発用DBだけを操作してください。

## 確認問題と答え

**Q. 詳細行のCategoryをforeachのたびにDB照会する？** いいえ。必要な列をSQLのJOINでまとめて取得します。
