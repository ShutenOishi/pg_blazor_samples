# 学習ロードマップ

## 前提と進め方

C#の基礎（変数、クラス、非同期の概念）が分かると進めやすくなりますが、初めて学ぶ人のために用語は最初に説明します。順番に進むことを標準とし、実務経験がある人は前提ステップを飛ばせます。

1ステップは**1つの中心概念と1つの動作確認**に絞ります。各ステップの理解を確認してから次へ進みます。所要時間は個人差があるため固定しません。

| 段階 | ステップ | 到達目標 | 外部依存 |
| --- | --- | --- | --- |
| Lv.1 画面とRazor | 01～10 | コンポーネント・イベント・入力フォームが作れる | 原則不要 |
| Lv.2 DI・サービス設計 | 11～20 | DI、ライフタイム、サービスの分離とテストを理解する | 原則不要 |
| Lv.3 MudBlazor UI | 21～30 | 業務画面に必要な部品と入力検証を使える | 原則不要 |
| Lv.4 PostgreSQLとEF Core 10 | 31～40 | NpgsqlとEF Coreで型・CRUD・寿命・排他制御を学ぶ | PostgreSQL 18 |
| Lv.5 一覧データ連携特化 | 41～60 | MudDataGrid/MudTable・検索・仮想化・編集・性能の選択と実証 | PostgreSQL 18 |
| Lv.6 Windows認証 | 61～70 | AD本人認証とDB側業務認可を区別し適用する | ドメイン参加環境・PostgreSQL |
| Lv.7 実務応用 | 71～80 | 性能・障害対応・運用の観点で改善する | 課題による |

## 初学者に合わせたプロジェクト増加

ステップ01ではWebプロジェクトのみを作成し、ステップ11でDIの意味を説明します。ステップ18でUnitTests、19でApplicationを既に追加しています。**EF Core 10のステップ31〜40では層別プロジェクトを追加せず、Web内のDataとServicesを使います。** PostgreSQLの結合確認は開発専用DBで実施します。詳細は[DI入門](di-for-beginners.md)と[アーキテクチャ](architecture.md)。

## 1ステップの学び方

1. 「このステップでできるようになること」を読む。
2. 実行条件（AD・DBの要否）を確認する。
3. 実行して画面やSQL結果を確認する。
4. 差分・仕組みの説明を読む。
5. 演習課題を自分で変更し、再度動かす。
6. 確認項目に合格したら次へ進む。

## 5ステップごとの学習コラム

ステップ05・10・15…80の直後に、通常16本＋特別編2本の計18本の理解を深めるコラムを配置します。単なる補足情報ではなく、「5ステップの関係」「実務の応用」「誤解と落とし穴」「確認問題・解答」「次への橋渡し」で構成します。

現在は[コラム01](columns/column01-05.md)、[コラム02](columns/column06-10.md)、[コラム03](columns/column11-15.md)、[コラム04](columns/column16-20.md)、[特別コラム05：ライブラリのDI](columns/column-library-di.md)を追加しました。コラム06もMudBlazorのテンプレート・DI・翻訳に対応して追加しました。コラム07〜09と用途別MudBlazor特別コラムまで追加します。コラム10〜12を追加し、コラム13〜17は後続ステップで拡充します。全16回の計画は[コラム一覧](columns/README.md)で確認してください。

## 代表的なチェックポイント

- **10終了**：フォームの入力、状態変化、検証エラーを説明できる。
- **20終了**：DI登録とライフタイムの違い、画面と業務ロジックの分離を説明できる。
- **30終了**：MudBlazorの表・ダイアログ・フォームを組み合わせられる。
- **40終了**：EF Core、Npgsql、日付・Range型、DbContextFactory、トランザクション、競合検出を説明できる。
- **60終了**：MudDataGridのItems/ServerData/VirtualizeServerData、MudTable、キーセット、編集・CSVの選択理由を説明できる。
- **70終了**：AD認証済みでもDB未登録・無効ユーザーは拒否できる。
- **80終了**：開発・セキュリティ・性能・運用の基本的な検証を再現できる。

## 実行環境に関する原則

ステップ01〜30は実ADやDBがなくても**画面と概念の学習**ができるよう、無害な固定データで構成します。DB・AD連携そのものは実接続を確認して初めて「検証済み」とします。ADのない環境で使うテスト用認証主体は自動テスト内に閉じ込め、実運用の認証手段として提供しません。

本番の配備先はWindows Server 2025 + IISです。ステップ71〜80で本番運用に必要な手順を学びます。各ステップの一覧は[サンプル一覧](sample-catalog.md)を参照してください。

## データ連携編の選択指針

Step26でDB不要のDataGridを学び、Step31〜40でEF Core 10とNpgsqlを身に付け、Step41〜60で実DBを使う一覧表示・検索・編集の設計を段階的に完成させます。まず[EF Core・Npgsqlの基礎](efcore10-data-access.md)を読み、[一覧表示パターンの比較](data-grid-patterns.md)から要件別の最適な方式を選びます。Step41〜70の教材・ソースも実装し、実DB試験で検証します。Step66〜70の業務認可は開発用データでの学習用であり、実機AD/IISの受入は未実施です。
