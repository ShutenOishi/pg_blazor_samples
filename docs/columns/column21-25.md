# 学習コラム06：MudBlazorのテンプレート・DI・翻訳を理解する

## 5ステップをつなぐ
Step21ではパッケージ・サービス・Providerを登録、Step22で画面を構成、Step23で日本語の入力、Step24でフォームの検証、Step25で一覧表とページャーの操作を学びました。

## テンプレートを使うメリット
新規開発ならMudBlazor.Templatesの生成物を学ぶことで、サービス登録・静的アセット・描画モード・画面レイアウトをまとめて理解できます。すでに動いている教材へは必要な設定だけを取り込み、既存ステップの構成を保持します。

## ローカライズは二層で考える

| 種類 | 採用する仕組み |
| --- | --- |
| テーブルなどライブラリ共通の文言 | MudBlazor.Translations |
| 業務画面独自のラベル・必須エラー | Razor側の日本語文字列 |
| 日付と数値の書式 | ja-JPのCultureInfo、RequestLocalization |

## 特別コラム05で学んだDIを再確認
```text
公式手順を読む → NuGetを追加 → AddMudServicesとAddMudTranslations
                 → Provider配置 → @inject ISnackbar → 操作する
```
自作するDIの仕組みを理解することも重要ですが、ライブラリが用意した登録・注入の契約を正しく使うことは、Blazorを始めやすくする重要な技術です。

## 確認問題と解答
**Q1. MudBlazor.Templatesで生成すれば翻訳の設定は不要？**  
A. いいえ。テンプレートの初期設定と翻訳パッケージの導入は確認を分けます。

**Q2. AddMudServicesだけで通知が表示できる？**  
A. いいえ。Providerと適切な対話型描画モードが必要です。

**Q3. 共通の翻訳と独自のエラーはどちらに書く？**  
A. 共通UIはMudBlazor.Translations、教材固有の説明・検証文はRazor側です。

**Q4. フォーム検証はサーバー側の認可の代わりになる？**  
A. いいえ。後続でデータアクセスと認証・認可を分けて実装します。
